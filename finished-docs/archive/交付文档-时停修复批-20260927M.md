## §0 一句话结论

时停的语义被补齐成一句可执行的规则：**冻的是战场，不是观察者** —— 凡"观察者自己"的东西（本体、座驾、
**他打出的弹丸**）走真实帧长；凡战场的东西（AI 的弹丸、粒子、命中判定）随世界帧长 0 一起停。
落地方式是一处**帧长单源** `specTimeShotDt(owner,rdt,dt)` + 七个消费点逐条解析，没有给任何系统加"时停特判"。
由此一次性消掉：静止炮弹隔空引爆（旧实测 404 血）、观战者连射线性堆对象（120 次开火 → 120 个 Mesh）、
巡飞弹制导被冻死、时停跨主菜单残留、海战音频独走真实时间、以及"停着却没有任何读数"。

## §2 落地口径（改时停相关代码前先读这一段）

1. **帧长单源**：`js/22b-speclayer.js` 的
   `specTimeShotDt(owner,rdt,dt)` —— 非时停一律返回 `dt`（**零行为漂移**）；时停时只有 `owner.isPlayer`
   的投射物返回 `rdt`；调用方没给 `rdt`（部分沙箱/直调探针）退化为 `dt`（冻结），不返回 undefined。
   归属判据用 **`shooter.isPlayer`**（全库射手字段：玩家 true / Bot·乘员 false —— 与 `fireBullet` 里
   "非玩家吃难度伤害分档"同一个字段），不另立一套"谁算玩家"。
2. **消费点（七个，新增系统照着接一处）**：`24-main` 把 `rdt` 传给
   `updateShells(dt,rdt)`（15-vehicles，逐发）· `updateFlak(dt,rdt)`（16-aircraft，逐发）·
   `updateNades(dt,rdt)`（13-combat，逐枚按 `thrower`）· `updateLoiters(dt,rdt)`（13-combat，按 `owner`）·
   `updateTracers(dt,rdt)`（08-effects，`spawnTracer` 新增第 4 参持有人 = 射手，`fireBullet` 唯一调用点带 `shooter`）·
   `updateCasings(dt,rdt)`（08-effects，整条链归玩家 —— 三处调用点全是玩家视角武器）·
   `updatePlayer(pdt,dt)`（20-player → 01-audio 逐艇）。
3. **`updateParticles(dt)` 故意不动**：冻结点上炸开的火焰/尘土就该定格在那里（池上限 280，有界）。
4. **明确不改的三条口径（不是漏洞，别当缺陷再修）**：
   ① 时停中观察者**照常开火并造成伤害** —— 用户既有裁定「幽灵坦克可对双方开火」+「不冻观察者」；
   ② 粒子不并入观察者链（定格是想要的观感）；③ 世界炮弹停在半空（冻结的战场就该静）。
5. **冻结帧的写法**：`if(!(sdt>0)) continue;` 整发跳过 —— 不能只让"位移"为 0 而让命中判定照跑
   （`hitD=step+0.5` 那种前瞻正是 P0-1 的成因）。
6. **HUD 读数的挂点**：顶部栏那段是 **10Hz 重绘**（`hudSlowT-=dt`），而时停下 `dt=0` ⇒ 挂在里面的读数
   永远不会出现。凡是"时停期间要即时反映状态"的 HUD，必须走**逐帧段**（`hudShow`/`hudText` 稳态零 DOM 写入）。

### 本批"首跑红"的定位记录（1 条判据过期 + 1 条自查抓到的设计坑）

1. **判据口径过期（非代码缺陷）**：`verify-specbatch` T10 的源码子串断言在找 `updatePlayer(pdt)`，而本批给该调用
   加了第二实参（世界帧长）⇒ 假红。修法：断言改为 `updatePlayer(pdt,dt)` 并注明"第二实参 = 世界帧长，
   本体链仍是 pdt"。**教训：接线类子串断言在"签名扩展"时会假红 —— 扩展签名要顺手更新所有读它的守卫。**
2. **自查抓到的设计坑（已改）**：P2-6 的读数第一版挂在顶部栏那段 10Hz 重绘里（`hudSlowT-=dt`），而时停下
   `dt=0` ⇒ **按下 K 之后顶部栏根本不再重绘，读数永远不会出现**（探针当时也测不到：它先手把 `hudSlowT` 归零了）。
   改成独立元素 `#specTimeInd` + `updateHUD` **逐帧**对账，并把探针 T7 改成"冻结帧 `updateHUD(0)` 也要亮"。
   **教训：判据要跑在被测的真实帧长上（dt=0 的那一帧），否则会把"永远不会发生"测成"通过"。**

## §5 待用户裁定 / 实机关注点

1. **观战特权的边界**：本批保留"时停中观察者照常开火并造成伤害"（依据是既有裁定「幽灵坦克可对双方开火」）。
   若实机觉得"时停 = 屠杀窗口"不合意，可加一支"时停下禁玩家侧伤害"的开关（单源在 `aimAssist`/`fireBullet` 之外的
   扣扳机入口，改动面很小）—— 但那会与幽灵坦克的既有契约冲突，需要明确裁定。
2. **实机关注点**（清单见 PLAN §四 2026-09-27M 条）：
   ① 时停中把炮弹打向人群附近 —— 它**不该**隔空引爆冻结点旁的人；
   ② 幽灵坦克连射几十发后 `tracers.length` / `shells.length` 不再线性增长（控制台直读）；
   ③ 海战图开时停：除自己在开的艇外应听不到破水/履带周期声（发动机静态余音会保持 —— 与陆战载具"随 dt 停住"
   同口径，不是漏改）；
   ④ 制导巡飞弹时按 K 立刻停/走；
   ⑤ 回主菜单再「继续游戏」，战场应当**在走**（旧版仍是静止的）。
3. **P2-7**（结构性：显式 frozen 分支）仍留长期项 —— 若后续要在时停里再加"能动的例外"（例如让某类 AI 继续跑），
   建议那时一并重构，而不是继续往 26 个 `update*` 上挂条件。
