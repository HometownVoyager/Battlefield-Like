## 1. ① 观战 F 键冲突（修）

### 根因（三条独立缺陷叠加，缺一条都不至于"严重冲突"）

| # | 现象 | 真因 | 位置 |
|---|---|---|---|
| a | 在艇上按 F **永远召唤幽灵坦克**，鱼雷/下船在真输入链上不可达 | `tryInteract()` 里 `if(player.spectator){…}` 分支排在 `if(player.onNaval){…}` **之前**并直接 `return` ⇒ 观战者一上艇，F 就被召唤吃掉 | `js/20-player.js:75`（改前） |
| b | 按一次 F 之后，**人还钉在艇上、却开着白车**（状态机劈叉） | `specVehBoard()` 不清 `player.onNaval` ⇒ `player` 同时挂"艇的驾驶位"与"幽灵坦克驾驶员"；`updatePlayer` 每帧仍走 `updatePlayerNaval`（`js/20-player.js:446`），驾驶权归艇、渲染归白车 | `js/15c-specveh.js:269`（改前） |
| c | 屏幕上提示"F 召唤并进入幽灵坦克"，而 F 实际不是那个语义 | `updateInteractHint()` 的观战分支同样排在最前，把鱼雷/下船的提示盖掉 | `js/20-player.js:747`（改前） |
| d | （取证时新发现）"步行 → 上艇"那一下提示**不刷新** | 该函数按 `sig` 指纹节流重算，指纹里**没有 `onNaval`**（也没有 `onVehicle.kind`）⇒ 上艇后提示停在上一条 | `js/20-player.js:734`（改前） |

**为什么 (a)(b) 会同时存在还看不出来**：沙箱探针大多直接调 `tryInteract`，绕过 19-input 的分支优先级；
而 (b) 的症状（人在艇上开着白车）在没有真输入链时不会显形。这正是用户"实机才报出来"的原因。

### 改法

1. **`tryInteract` 改成语义优先级栈**（用户裁定①）—— 一个 F 键，同一时刻只有一条语义生效，按玩家**当前状态**从高到低判：
   - ① 幽灵坦克上 → `F` = 下车（收车）
   - ② 海战舰艇上 → `F` = 深水：鱼雷 / 可涉水·搁浅：下船（沿用 `navalCanFootExit` 单源判据）
   - ③ 其余（步行/游泳）→ `F` = 召唤并进入幽灵坦克
   观战者**只在前两态放行**，其余一律走召唤 ⇒ 结构上不可能再撞（用户裁定②：观战者不走路登艇；
   想开艇请从部署界面选舰艇出生项 —— 那条路不经过本函数）。
2. **两个座位字段互斥，两个方向都补**（治 (b) 的结构性病根）：
   - `specVehBoard()`：上幽灵坦克瞬间 `navalSeatRelease()` 交还海战座位（同一条 20a 路径，不另写一套）；
   - `navalBoard()`：上艇前 `specVehStow()` 收掉幽灵坦克（幂等，非观战路径下什么都不做）。
3. **提示行与 `tryInteract` 逐级同序**（治 (c)）：三条语义各自先判自己的状态，只有都不成立才轮到观战召唤。
4. **提示指纹补 `onNaval`(bit 2048) 与 `onVehicle.kind==='ghost'`(bit 4096)**（治 (d)）：
   只看 `onVehicle` 那一位不够 —— `tank↔ghost` 切换时该位恒为 1。
5. **HUD 操作行补 F 的"下船"语义**：`22-hud` 原来永远写 `[F] 鱼雷`，浅水/搁浅（F 实际=下船）时读数是错的。
   顺手把观战横幅的 `F=幽灵坦克` 改成 `F=按状态(…)`，并补齐 i18n 英文条目。

### 实测（`dev/_fkey-selfcheck.js`，16/16）

**判据全部调用游戏自己的接口**（`tryInteract` / `specVehBoard` / `navalBoard` / `updateInteractHint` …），不重写第二套状态机；
沙箱里 `15c`/`20a`/`20-player` 都是**真文件**（只桩掉地形/音频等无关依赖）。

| 用例 | 结果 |
|---|---|
| 观战 + 在艇上 + 深水按 F | `craft.fireTorpedo` 调用 1 次；`SPECVEH` 仍为 null；`onVehicle` 为空 ✓ |
| 观战 + 在艇上 + 浅水按 F | 走"下船"跨出（`navalExit` 已置），且**不发**鱼雷 ✓ |
| 观战 + 在幽灵坦克上按 F | 下车（`onVehicle` 清空 + `SPECVEH` 置空）✓ |
| 观战 + 空手步行按 F | 召唤并直接上车（`playerDriven=true`、`onVehicle===g`）✓ |
| 上幽灵坦克（绕过 F 直接调） | 自动交还海战座位（`onNaval=null`、`craft.playerDriven=false`）✓ |
| 上艇（在车上时） | 自动收掉幽灵坦克（`onVehicle=null`、`SPECVEH=null`）✓ |
| 四种状态的提示文案 | 各自正确，且观战在艇上时**不出现"幽灵坦克"** ✓ |
| 座位字段直接变化 | 提示必须跟着切 ✓ |
| 普通玩家在艇上按 F | 仍是鱼雷（观战改动不影响常规路径）✓ |

**阴性对照**（证明判据非空转，两条都实测过）：
- 把新增的 `onNaval` 指纹位删掉 ⇒ 用例 ⑭b 当场转红（`步行 → 置 onNaval` 后文本**没变**）；
- 第一版指纹测试借用 `navalBoard()` 改状态 ⇒ **阴性对照照样全绿**（因为 `navalBoard` 内部自己会刷一次提示），
  该写法已废弃并改成直接赋值座位字段 —— 这条教训写在测试文件的注释里。

## 2. ② 两台两栖车重做

### 用户判词的几何本质（取证：`dev/_modelview.js` 离屏渲染 + 逐件 AABB）

- **LVT(A)-1 = "散架"**：浮力箱是**贴在舷侧的 0.10m 薄缘**、艏/艉各一块**外挂上翘唇板**、首上另铺一块斜板 ——
  侧视就是"零件挂在车壳外面"；浮箱缘/唇板/挡水沿顶点**探出车体轮廓**（整车宽就是被那 0.06m/侧撑出去的）。
- **カミ = "棺材"**：车体 = 方箱，前后两块**与车体等高的大方浮筒**（0.94×boxH）⇒ 侧视就是一口箱子插着两块板；
  浮筒是"方块 + 一块斜板"（`nmPontoonBevel`），两个件靠面贴合。

### 改法（用户裁定④：史实剪影 + 一体化）

**核心手法：车体从"多个 Box 拼"改成"一张断面放样曲面"**（新增 `nmLoft`）——
断面 = 8 点（底右 → 舷侧折角外缘 → 折角上收 → 甲板右 → 甲板左 → …），相邻站位同序号顶点连成四边形。
一旦车体是"一张面"，**浮力箱就成了车体的舷侧折角、艏部收窄上翘就成了面上的转折**，件与件之间不再有"贴上去的板子"。

| 项 | LVT(A)-1 | カミ |
|---|---|---|
| 车体 | 断面放样：底宽 0.646 → 折角外缘 1.000（浮力箱即折角）→ 甲板 0.958；艏部收窄+船底上翘（跳板艏）；方艉带**艉门** | 断面放样：船形（前倾艏柱、船底上收、艉部收窄 0.66）；折角更圆（wc−wb=0.236 vs LVT 0.354） |
| 分色 | 下水线以下 `M.tone` / 以上 `M.body`，**折角线即分色线**（史实 LVT 双色涂装），两片共享折角棱（不重叠、不留缝） | 同左 |
| 行走机构 | 史实布局：**负重轮压在履带带条外侧**（带条收窄到 0.090·hullW，轮宽 0.12·hullW）+ 两端**主动轮/诱导轮**（8 棱鼓）给带条封口 | 同左 |
| 浮筒 | —（浮箱即车体折角） | **船形浮筒**：断面放样（艏/艉柱收口 + 舯部等宽），内端**套住车体端部**（咬合 0.20×筒长）+ **连接卡扣**（史实可拆卸件） |
| 尾部 | 开放艉架（两根支柱，看得见桨）+ **三叶桨**（桨毂+3 叶，合成一件几何）+ **每舷一片舵** + 舵间横梁 | 同左 |
| 涂装分件 | 上体/下体/履带·管件/锈蚀/钢件/舱盖/舷号/旗 **8 套材质**（每台全新，无跨车共享） | 同左（含浮筒独立色） |

**尺寸口径（新增 `S.bodyL`）**：カミ 的 `spec.hullL=7.40` 是**含前后浮筒的全长**（史实 Ka-Mi 7.42m 即含浮筒，
车体只有 4.8m）⇒ 车体 = `0.595×hullL`，**行走机构/艉部/旗杆一律按车体长派生**。
旧版按总长算，艉架/桨/舵被甩到车体之后约 1.6m（侧视读作"悬空的一组零件"）—— 本轮修掉。

## 3. 顺带扫出并修掉的三处相邻缺陷

| # | 缺陷 | 性质 | 位置 |

| ① | 提示刷新指纹漏 `onNaval` / `onVehicle.kind` | **真缺陷**（用户报的"冲突"在 UI 上的直接来源之一） | `js/20-player.js` |

| ③ | `verify-seabatch` 第⑦条**自身语法错**、从未真跑过；且"顶步"读数取错项 | **判据缺口**：段内重复声明 `let stairTop` ⇒ 整条抛 `Identifier has already been declared`（报的是脚本错，不是楼梯结论）；`g.steps[0]` 取到的是**最下一级**（steps 自下而上建，`i=n−1` 才是顶）⇒ `topDev` 恒为 `−sr×(n−1)` | `dev/verify-seabatch.js` |

## 4. 请实机验收（用户代为操作；有疑问随时问）

### A. F 键（三项都要在**观战模式**下试）

1. **幽灵坦克上按 F** → 应下车且**车立刻消失**（收车），不是"下车后白车还停在那"。
2. **乘舰艇出海到深水，按 F** → 应**发射鱼雷**（右下角弹"鱼雷发射!"、艇上有管口特效）。
   同时确认屏幕上提示行写的是 `[F] 鱼雷`（**不是**"召唤幽灵坦克"）。
3. **把艇开到浅滩/搁浅（或贴着岸），按 F** → 应**下船**（人从舷侧/艏跳板走到岸上），提示行写 `F 下船`。
4. **上岸后（空手步行）按 F** → 应**召唤并进入幽灵坦克**（白车在身边显形、人直接坐进去）。
5. **走路/游泳靠近一艘本方艇按 F** → 按裁定②**不应上艇**（应召唤幽灵坦克）。想开艇请从**部署界面**选 ⚓ 舰艇出生项。
6. **HUD 操作行**：在深水艇上尾行应是 `… · [F] 鱼雷`；在浅水/搁浅艇上应是 `… · [F] 下船`。

### B. 两台两栖车（外观）

请重点看这三点（其余请随意挑刺）：

7. **LVT(A)-1**：舷侧那条折角是否读作"浮力箱"而不是"贴了块板"；侧面是否还有**支棱在外的小板子**（旧版是浮箱缘/艏艉唇板/挡水沿）；
   负重轮是否**压在履带外面看得见**（旧版是一条黑带遮住轮子）。
8. **カミ**：整体是否还像"棺材"（方箱 + 两块方板）；前后浮筒现在应是**船形收口**、并且**套在车体上**（有连接卡扣）；

9. **两台的艉部**：桨是否**看得见**（旧版桨被后板包住）；每舷一片舵 + 舵间横梁；桨叶与艉架/舵之间应有明显缝隙。

  改法是把 `spec.hullL` 调到 8.6 左右（= 4.8m 车体 + 浮筒），**一行数据**，建模端自动跟随（`NM_PONT_L` 等全是比值）。
- **LVT 整车长 +11.1%**：全部来自艉架/桨/舵（车体本身严格 = `hullL`）。若越界敏感，可把 `NM_PROP_AFT`(0.032→0)
  与 `NM_RUD_AFT`(0.15→0.10) 各收一档；但会牺牲桨叶净空余量（现为 0.129/0.149，红线 0.10）。
- **`15e` 不再用 `BoxGeometry.applyMatrix4/toNonIndexed`**：桨几何改成逐点算 —— 那两个方法在 dev 沙箱的最小几何桩里没有，
  一个纯视觉件不该把 `15e` 钉死在完整 three API 上（旧写法会让 `_naval-selfcheck` 整型回落到兜底盒）。
