## 1. 反舰炮台浮空三圆柱（修）

### 取证
`js/15f-battery.js` 的 `_buildModel` 里有个局部→世界坐标助手：

```js
const L=(lx,lz)=>[x+lx*cs+lz*sn, z-lx*sn+lz*cs];   // 传入局部偏移, 返回**世界**坐标
```

两处把它当成「组局部坐标」用了（组 `grp.position=(x,g,z)` 且 `grp.rotation.y=face`）：

| 位置 | 现状写法 | 后果 |
|---|---|---|
| ⑤ 待发弹堆 `15f:264-268` | `sh.position.set(p[0]-x, g+0.13, p[1]-z)` | y 又加了一次场地标高 ⇒ 世界高 ≈ **2×场地高+0.13**（岬角 8~9m ⇒ 约 16m 高空）；水平被 `face` 转了两次 ⇒ 位置也偏 |
| ⑦ 测距仪 `15f:292-302` | `rfp=L(2.35,1.35)` 后同样减 `x/z` | 同一类错：三脚架/测距箱被 `face` 旋转两次，落在炮位外的错方向 |

这就是截图里"意义不明的浮空三圆柱"（0.10×0.70 的三发待发弹）。**击毁态同样存在**：弹堆是纯视觉件，不参与塌毁链，所以修一次两边都好。

同文件其余 3 处 `L()` 用法（`ammoCratePit` / `coverPoints` / `BUILD_REG`）传的是**世界坐标**，是对的，不动。

### 改法
- 弹堆：直接给组局部坐标 `(-1.05+i*0.36, 0.13, -2.05)`，保留 `rotation.z=HPI / rotation.y=0.3`。
- 测距仪：三脚架腿 `(2.35+sin(d)*0.22, 0.58, 1.35+cos(d)*0.22)`、测距箱 `(2.35,1.24,1.35)`、镜筒 `(2.35,1.28,1.59)`。
- **只动视觉**：碰撞圆柱 `cyl`、掩体点、`BUILD_REG`、炮口/射界/冷却一行不改。

### 验收判据
- 新增几何断言：`grp` 全部子件 AABB 落在 ±`BATTERY_PAD_HW` 内、y ∈ [0, 3.2]；弹堆与平台/座圈无穿透。
- 真浏览器近景截图：正常态 + 击毁态各一张（前后对比）。

## 7. 两栖车浅水搁浅掉血（修）——含"你自己思考一下对不对"

### 取证（真浏览器 + 真 W 键输入，探针 `dev/tmp-shallow-amph.js`）
沿 x=0 做水深扫描，LVT（`draft0=0.40`、`wadeDepth=0.55`）：

| 状态 | 水深 | 实测 |
|---|---|---|
| 满血 | 0.80~1.00m | 浮航态；速度被压到 **1.12 m/s**（正常 5.4）；**4 HP/s 擦礁掉血**（实测 75 帧掉 15 HP） |
| 满血 | 0.638m 起步 | 起点仍是浮航态 ⇒ 切履带态前先掉 **7.2 HP**，切态后才能全速走 |
| 满血 | 0.45~0.55m | 履带态：速度 3.2~3.9 m/s，**0 掉血**，前进/倒车都正常 |
| 进水后 `flood=0.35`（吃水 0.583） | 0.64m | **`state='ground'`**、前进推力归零、速度 0、3.75s 只挪 1.1m、掉 11.4 HP；倒车 3.75s 只退 1.86m |

### 根因
`15d-naval.js` 同一条 `_integrate/drive` 里混用了两套阈值：
- **艇的吃水** `draft` 用来判 `grounded`（`d<draft` ⇒ 前进推力 0 + 刮擦）与 `shallow`（`d<draft+0.45` ⇒ 0.40 速度 + 4 HP/s）；
- **两栖车的换态阈值** `wadeDepth=0.55` 才是它"浮 / 履带"的开关。

于是：0.55~0.85m 这条**为木壳艇设计的擦礁带**，两栖车照吃；而一旦进水（`draft>wadeDepth`），它就落进"浮航态却吃水不足"的夹缝 —— 永远 ground、前进无推力、只能倒车。

### 我的判断（回答"两栖车因为水浅而受损你自己思考一下对不对"）
**不对，应当取消。** 三条理由：
1. **设计语义**：两栖车的存在意义就是冲滩。履带态的浅水阻力已由 `d>0.15 ⇒ ×0.78` 表达，再叠"龙骨擦礁"是把艇的惩罚错挂到车上；
2. **几何自洽**：健康两栖车 `draft(0.40) < wadeDepth(0.55)` ⇒ 它**永远不会**在浮航态触底，那条擦礁伤害在物理上无从发生，纯属误伤；
3. **可玩性**：现在的结果是"上岸前先掉一截血、速度砍到 1.1 m/s，一旦进水就彻底卡死在浅滩"——玩家完全无法理解，且没有操作能避免。

⇒ 采用用户选的**「履带优先」**：
- 擦礁伤害 `shallowScrub` **只对 `kind==='boat'`**；
- 两栖车**不进入 `state='ground'`**（履带恒可前进，进水后也能自己爬出去）；
- "顶住浅水线"的闸门对两栖车改用 `wadeDepth`（不是 `draft`），它到 0.55m 就切履带态继续冲滩；
- 浮航态的减速保留（`wadeSpdMul` 0.45 + 涉水阻力），这是"水里比陆上慢"的合理表达，不再叠加二次惩罚。

### 验收判据
- 重跑 `dev/tmp-shallow-amph.js` 扫描：**全水深 0 HP 损失、0 帧 ground、浅水仍能持续前进**（对照本批前数据）；
