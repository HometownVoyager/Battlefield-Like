### 2.4 `wc`（车重等级）+ 炮塔缩放（第 6 条）
- 每辆坦克的 `tk` 里新增 `wc:'light'|'med'|'heavy'`（**不要复用 `heavy` 字段**：那是"同阵营第二辆"的槽位标记，T-26 也写着 `heavy:true`）。
- `tkSpec()` 派生 `S.turScale`：`light→0.82 / med→1.0 / heavy→1.15`。
- `tankBuildTurret` 用 `S.turScale` 缩放炮塔本体 + 座圈 + 炮盾 + 炮管半径（炮管长度仍走各自的 `barrelL`）。
- **几何不变量（契约修订 v2，Lead 2026-09-21 追加）**：炮轴恒在 `TB_AXIS=1.93`（`muzzle.y` / `aimPitch` / `coverPoint` 全锁它，**一行都不许改**），而炮塔顶面 = `ringY + t.h`。无脑乘 0.82 会让 4 辆轻坦的顶面掉到炮轴下方（九七式 1.948 / 维克斯 1.975 / T-26 1.968 / 九七式缴获 1.946，全部 < 1.93+0.14）⇒ 观感是"炮管从炮塔顶上飘出去"。故 **h 必须加下限钳制**：
  ```js
  const hScale=Math.max(t.h*S.turScale, TB_AXIS-S.ringY+0.14); // 顶面至少高出炮轴 0.14m
  ```
  `w`/`l` 仍全量缩放（M26 2.875 vs 九七式 1.607 = **1.79×**，这就是"大小坦克的头不一样大"的量化口径）。
  实测表见本轮 Lead→tank-core 的消息；`dev/verify-vehmodels.js` 的管口对位断言必须继续过。

## 三、契约 A：载具机枪过热（第 3 条）

**对象**：①坦克同轴机枪（`Tank.firePlayerMG` / `turretAI` 的 `fireMG` 分支）②艇载机枪与副武器（`NavalCraft.fireMG` / `fireSecondary`）。
**排除**：幽灵坦克（`15c-specveh.js`）——不积热、不显示条。

**统一对象字段**（每个带热量的载具实例上）：
```js
this.heat=0;            // 0..1
this.heatLock=false;    // 过热强制停火标记
```
**统一规则**（必须两处同式，写成共用函数，禁止各写一份）：

```js
// 建议放在 15-vehicles.js（tank-core 拥有），15d-naval.js 调用同一份。
function vehMgHeatTick(v,dt,firing,isPlayer){
  const C=VEH_MG_HEAT;
  const cool=isPlayer?C.coolPlayer:C.coolAI;
  // 玩家：开火时不散热；AI：常散（与既有 MG42 口径逐字一致）
  if(!(isPlayer&&firing)) v.heat=Math.max(0,v.heat-dt*cool);
  if(v.heatLock&&v.heat<=C.unlock) v.heatLock=false;
  if(v.heat>=1&&!v.heatLock){ v.heatLock=true; /* 过热提示音由玩家侧出 */ }
}
function vehMgHeatAdd(v){ v.heat=Math.min(1.2,v.heat+VEH_MG_HEAT.heatPS); if(v.heat>=1) v.heatLock=true; }
function vehMgCanFire(v){ return !v.heatLock&&v.heat<1; }
```
- 开火门：所有载具机枪开火前 `if(!vehMgCanFire(this)) return false;`，开火后 `vehMgHeatAdd(this)`。
- 每帧在 `update()` 里调 `vehMgHeatTick(this,dt,<本帧是否开火>, this.playerDriven)`。

**HUD（sea-hud 实现）**：
- `index.html` 新增 `<div id="mgHeatWrap"><div id="mgHeatFill"></div></div>`（放在既有 `#heatWrap` 之后）。
- `#heatWrap` 继续表示**主炮装填**（现状不变）；`#mgHeatWrap` 专表**机枪热量**。
- 显示条件：玩家在载具上（坦克/艇）且该载具带机枪 ⇒ 显示；幽灵坦克 ⇒ 不显示。
- 过热时条变红并出一次提示音（`AudioSys.metalSlide(0.4,0.3,400,200)` 与固定 MG 同档）。

**验收判据**：
- 连打 71 发（±2）后 `heatLock=true`，此后开火请求全部被拒；
- 停火后 `heat` 按 0.22/s（玩家）/0.15/s（AI）单调下降，降到 0.35 解锁；
- 幽灵坦克连打 200 发 `heat` 恒 0；
- 艇载机枪同判据。

## 四、契约 B：三人车组（第 7 条）

> **契约修订 v3（Lead 2026-09-21 用户裁定）**：三人的"人"**不从士兵池里出**。
> 用户的第二次裁定是：**每车 = 1 名真实 AI 车组（现有 `crewBot`）+ 2 个"乘员名额"（轻量记录，不算独立士兵）**。
> 起因：各图 `tankN` 是 2~8，而 `BOTS_PER_TEAM=11` —— 若每车真配 3 名 Bot，诺曼底一队会从 11 人涨到 21 人（+91%），
> 斯大林格勒 14→30 人，战场人数与重生压力几乎翻倍，属于用户未要求的平衡破坏。
> **v2 的 `crewMates` 真 Bot 编制作废**（代码里已有的实现要回退）。

**数据结构**（全部在 `15-vehicles.js` 的 `Tank` 上）：
```js
tank.crewBot                 // 不变：唯一跑 AI 的驾驶员（"AI 算法仍是单个算法控制"）
tank.crewSlots=[recA,recB]   // 新增：2 个轻量乘员名额记录 {name,deaths,kills,score,alive,isCrew:true,damage(){}}
                             //   不进 soldiers / combatants（否则会被索敌、被子弹命中、被主循环更新）
tank.crewRoster()            // 车内实际在编的乘员：驾驶员(AI 或玩家) + 2 名额；空车返回 []，另见 mannedCrew()
tank.crewSlotsAlive()        // 口径: 驾驶员在场(crewBot 或玩家在车) ⇒ 2 个名额成立; 否则 0
```
**车毁结算（`Tank.die`，v3 定稿）**：
```js
const driver = this.playerDriven ? (player.alive?player:null) : (this.crewBot||null);
if(driver){
  // 真人驾驶员各走自己的既有死亡链（1 死 / 1 票 / 1 杀），一行汇总都不加：
  //   AI  crewBot → b.crewKill(attacker)   (bots 提供; 走 die() 全链, 只抑制本乘员那条 killfeed)
  //   玩家 → player.damage(999,attacker,false)

}else{

  tickets[this.team]=Math.max(0,tickets[this.team]-(this.def.heavy?TICKET_COST.tankHeavy:TICKET_COST.tankLight));

```
`settleCrewSlotDeath(slot,attacker,team)`（tank-core 实现，放 15-vehicles.js）：
```js
function settleCrewSlotDeath(s,attacker,team){
  if(!s||!s.alive) return;
  s.alive=false; s.deaths=(s.deaths||0)+1;
  tickets[team]=Math.max(0,tickets[team]-CREW_TICKET_EACH);
  if(attacker){
    attacker.kills=(attacker.kills||0)+CREW_KILL_EACH;
    if(!attacker.isPlayer) attacker.score=(attacker.score||0)+SCORE_TABLE.kill;
    else if(typeof onPlayerKill==='function') onPlayerKill(s,false);   // 玩家记分唯一入口 (21-match): 走名额不双计
  }
}
```
- **算术自证**：AI 车 = crewKill(1) + 2 名额 = **3 死 3 票 3 杀**；玩家车 = player.die(1) + 2 名额 = **3 死 3 票 3 杀**；空车 = 装备票（旧口径）。
- **占位**：玩家上车仍走既有路径（原 `crewBot.dismountVehicle(false)` 下车归建）⇒ 车内 = 玩家 + 2 名额 = 3 人；玩家全权操控。
- **车组全程在车内**：删除 `<25% hp 弃车`（`15-vehicles.js:455`）与 `stuckT>=4 下车`（`:899`）两条自动下车（卡住仍走倒车+重寻路自救）。
- **重生**：`respawn()` 把 2 个名额复位 `alive=true`（deaths 累计保留 —— 同一个人再上车）。
- **编制生成**：`23-deploy.js` 恢复"每辆坦克 1 名 Bot"（删掉 v2 的 `CREW_N-1` 循环），**不新增任何 Bot**。
- **记分板**：`22-hud.js` 的 `crewRoster()` 读数天然变成 3 ⇒ `#vehHpNum` 显示 ` · 乘员 ×3`；名额不进 `combatants`，故记分板不新增行（现有 `seahudTankOf` 对真驾驶员仍显示"坦克名·乘员"，`t.crewMates` 引用有 `&&` 守卫，字段移除安全）。

**验收判据**：
- 开一局后全队 `soldiers.length` **与改造前一致**（不因三人车组增加）；`crewRoster().length===3`（有车组时）；
- AI 车被击毁：击杀者 `kills +3`、该队 `tickets -3`、2 名额 `deaths` 各 +1 且 `alive=false`、crewBot 死 1 次 ⇒ 合计 3 死；

- 一次车毁的 killfeed 行数 ≤ 2（坦克 1 行 + 玩家在内时玩家死亡 1 行）；
- 全仓库只有一处调用 `tankPerceive/driveAI/turretAI` 的入口（单算法）。
- **AI 算法仍是一套**：只有 `crewBot` 走 `tankPerceive/driveAI/turretAI`；`crewMates` 每帧**不做任何决策**，只 `pos.copy(tank.pos)` + `mesh.root.visible=false`。
- **玩家上车**：走既有路径（原 `crewBot.dismountVehicle(false)` 下车归建）⇒ 车内 = 玩家 + `crewMates` = **3 人**。玩家全权操控（`playerDriven=true`，AI 不再接管）。
- **车组全程在车内**：删除 `<25% hp 弃车`（`15-vehicles.js:455`）与 `stuckT>=4 下车`（`:899`）两条自动下车；卡住仍走"倒车+重寻路"自救。
- **车毁（`Tank.die`）**：一次性结算 **3 死**，但**汇总行必须删掉**（契约修订 v2，见下）：
  ```js
  // 每名车内活着的乘员各走一次"完整死亡链"，3 人 ⇒ 天然 3 死 / 3 票 / 3 杀：
  //   AI 乘员 (crewBot + crewMates)：b.crewKill(attacker)  ← 走 die() 全链(含 tickets-1 / kills+1 / 记分 / 布娃娃 / 清理),
  //                                                          只抑制"每个乘员各出一条 killfeed"(否则一次车毁刷 4 行)
  //   玩家在内：player.damage(999,attacker,false)          ← 既有链(18-game:69/72 自己 -1 票 +1 杀)
  // ★ 绝不要在这里再写 attacker.kills += CREW_N / tickets -= CREW_N —— 那是双计（变成 6 杀 6 票）
  addKillfeed(attacker,{name:this.name+' · 乘员×3',team:this.team,isPlayer:false},false); // 一次车毁只出一条战报
  ```

- **契约修订 v2（Lead 2026-09-21 裁定 ②·双计事故）**：初版契约的 `Tank.die` 片段既让乘员走 `damage()` 全链、又额外加 `attacker.kills+=CREW_N / tickets-=CREW_N`，实测会变成 **6 死 6 杀 6 票**（AI 车）以及玩家在内时的 6/6/6 变体。修正为**唯一记账源 = 每名乘员的既有死亡链**：`Bot.die()`(14-bots:316/318) 自己 `tickets-1 + kills+1 + 记分`，`player.die()`(18-game:69/72) 同样。`Tank.die` **只负责"让 3 个人各死一次"**，不碰汇总。
  - 算术自证：AI 车 = 3×crewKill ⇒ 3 死 3 票 3 杀；玩家车 = 玩家链(1) + 2×crewKill ⇒ 同样 3 死 3 票 3 杀。两种情形同式，无特例。
- **重生**：`respawn()` 必须重新配满 `crewMates`（2 名）+ 由 23-deploy/14-bots 重新配 `crewBot`。
- **编制生成**：`23-deploy.js` 的 `startMatch` 给每辆坦克创建 3 名 Bot（1 名 `spawnInVehicle(t)` + 2 名 `spawnInVehicle(t,true)`）；`Bot.spawnInVehicle(v, asMate)` 第二参为真时**不写 `v.crewBot`**，只 `push` 进 `v.crewMates`。
- **战报/记分板**：3 名乘员都是 `soldiers`/`combatants` 成员（`new Bot(...)` 即注册），因此记分板天然出现 3 行；`22-hud.js` 的坦克乘员行需显示 `坦克名·乘员` 而非空名。

**验收判据**：
- 开局每辆坦克 `crewRoster().length === 3`；
- AI 车被击毁：击杀者 `kills +3`（**不是 +6**）、该队 `tickets -3`（**不是 -6**）、3 名乘员 `alive===false`、3 人 `deaths` 各 +1；

### 12.2 上半身镜像的数学依据（写进注释，避免下一批又改回去）
镜像平面 x=0（x→-x）下旋转矩阵的共轭 `M R M⁻¹`：`Rx(θ)→Rx(θ)`（**不变**）、`Ry(θ)→Ry(-θ)`、`Rz(θ)→Rz(-θ)`。
Euler 顺序为 XYZ 时**逐分量成立**，所以：
- **肩链的 `rotation.y` / `rotation.z` 目标值要整体取反**（`shRy/shLy/shRz/shLz`）；
- `rotation.x`（前后摆）**不动**；
- 姿态**数值本身不重调**，只在写回处乘 `UPPER_MIRROR` —— 两边（Bot 与玩家）共用同一个符号，杜绝各调一套。
