## 二、逐条说明

### 第 1 条 · Bot 坦克完整交战 AI + 难度分档削弱 + 车体互撞

**根因**：坦克车组从来没有"敌车感知 → 交战决策"这一层，`turretAI` 选目标极窄；`enemyTankNear()` 只服务反坦克步兵。所以两车相遇时互不理会。

**实现**（`js/15-vehicles.js`）
- `TANK_AI` 三档表（L64-99）：视距 **188/235/294m**、反应 **1.36/0.80/0.45s**、主炮散布 **0.0234/0.0110/0.0056 rad**、火力距离 **140/200/260m**；粗粒度旋钮（视距/散布/反应）**逐值取自 `00-config.js` 的 `DIFF_TABLE`**，不复制数值。
- `tankPerceive()`（L632）：前向视锥 + `raycastWorld` LOS + 7Hz 节流 + 记忆；**从不穿墙索敌**。
- `tankCoverPoint()`（L690）：hull-down 射击位（利用地形起伏）。
- `pickTankTactic()`（L725）：压上 / 绕侧 / 追残血 / 抢掩体 / 拉开距离，按难度限权（新兵 `chase=0/flank=0`）。
- `vehiclePushTanks()`（L117）：坦克↔坦克分离推挤，**位置下限 2.9m > 车宽 2.6m**（构造性保证不穿模）。
- `tankFireLineClear()`（L167）：友军压在弹道上时不开火（走廊 3.4m）。

**"不超雄"的量化边界**：新兵档首次开火延迟 2.25s、散布标准差 0.00580；精英 1.25s / 0.00135 —— 差 1.80× 与 4.28×。精英**仍有散布**（未被做成"零误差狙击手"）。

**一个探针逼出来的真 bug**：正面对撞到"两车前圆重合"的退化位形时，圆心连线方向会掉头指向车体内侧，按它推等于把两车互相推穿（实测中心距只剩 **0.16m**）。改为"量值取最深圆对穿透、方向取车心连线"后为 6.34m。

**已知边界**：空车不参战（交战层跑在 `crewBot` 分支，而 `14-bots.js` 的既有规则不接"停着的车"）—— 若再看到"坦克互相无视"，先确认那辆车有没有车组。步兵反坦克**没有**同款友军弹道预检（有意的口径差异：步兵是各自瞄准）。

### 第 3 条 · 观战连狙可攻击双方

**根因**：`raySoldiers()` 的敌我过滤只认 `shooter.ffAll`，而 `ffAll` 只在**驾驶幽灵坦克**时为 true ⇒ 观战连狙打不到"开局所选阵营"。

**实现**：新增 `coFfFire(shooter) = ffAll || ffSpecSniper` 作为**单源判定**（`13-combat.js:16`），步兵命中/载具命中/压制惊动三处共用，避免"能打人不能打坦克"的不一致。`ffSpecSniper` 由 `playerFireTick` 按**手上这把枪**的 key 逐帧同步、开火瞬间落定。

**口径精确性**：用户要求"只有观战连狙可打双方"——实测观战者持观战连狙打友方 100→25；换普通步枪 100→100；幽灵坦克主炮 `team=-1/520` 与 `ffAll` 语义未动；刺刀不吃该标记（否则观战者握连狙贴队友按 V 会捅死友军）。观战者开火仍不压制/不惊动、不会引来 Bot 还击。

### 第 4 条 · 第三人称切换

**实现**：`thirdPersonOn/playerEyePos/playerFireOrigin/tpAimPoint/playerAimDir/thirdPersonCamera`（`20-player.js:801-905`）。相机后拉 3.6m + 抬高 0.42 + 右肩 0.5，`raycastWorld` 防穿墙收距（下限 1.25m），地面下限 0.35m。

**键位**：桌面 **U**；移动端新增触控键 **#tView「视角」**（复用同一份 `toggleThirdPerson()` 单源，**直调**而不是派发 `KeyboardEvent` —— 触屏没有 Pointer Lock，派发会被闸门挡住且在 iOS 上 `KeyboardEvent` 构造器不接受 `code`）。

**互斥语义**：开镜(ADS)自动回第一人称、松镜自动回；载具（追尾/C 车长镜）、巡飞弹（F）、跳伞、游泳各有自己的视角，本开关不接管。

**最易埋 bug 处已验证**：第三人称下弹道起点 = **角色眼位**（不是相机位置），方向 = 眼位 → 准星命中点。实测起点距眼位误差 **0.00e+0m**、距相机 3.60m、到准星命中点垂距 **1.39e-17m**；端到端"准星指着 20m 外友军开一枪"命中掉血。

### 第 6 条 · 主菜单没有隐藏战斗 HUD

**根因（真浏览器实测，非推测）**：用户截图里的"主页"实际是**部署界面**。`startGame()` 摘掉 `body.inMenu` 后 `showDeploy(true)`，而 `#deploy` 的 `.screen` 背景只是 **94%~97% 不透明**的径向渐变（`css/style.css:245`，z-index 20），底下 z-index 10 的 `#ui` 里 **11 个模块**（小地图 190×190、血条 [26,832,230,49]、弹药面板 [1417,796,127,85]、顶栏 682×114…）仍 `display:block` 且 opacity=1 ⇒ 从遮罩底下透出来。

**已排除**：`body.inMenu` 的增删共 6 处、逻辑全部正确；主菜单/面板切换/结算/返回主界面**每条路径上 `#ui` 都正确隐藏**（用 DOMTokenList 补丁打调用栈时间线核实）。

**修复**：新增 `body.inDeploy` + CSS 同构规则（**不复用** `inMenu`，避免污染其"菜单/结算"语义），挂摘点覆盖**全部 8 条收起 `.screen` 的路径**（含 `togglePause`/`endMatch` 这两处易漏点）+ 主循环每帧权威对账（稳态零 DOM 写入）。

**实测**：部署期 `body=inDeploy` / `#ui=none(rendered=false)` / **真渲染 HUD 模块 0**（修前 11）；战斗期 14；主界面 0。

## 五、过程记录：本批踩过的三个坑（供后续批次警惕）

1. **多人同改一个文件的语法中间态**：`js/14-bots.js` 与 `js/00-config.js` 各出现过一次"少/多一个大括号"的中间态，全队沙箱探针与整局加载链一起停摆。缓解措施：每次落盘后立刻 `node --check`；跨人共享文件一次 `edit` 只做一处；`dev/_brace-scan.js` 用于快速定位。
2. **探针判据本身的假阳/假阴**：①"祖先盲"计数（见上）；②把 `window.player` 当游戏里的 `player` 用 —— 后者是顶层 `const`，**词法绑定不会成为 window 属性**，于是状态判据恒为 false，把正确行为报成 FAIL；③console 里那条不带 URL 的 `404` 文本滤不掉 favicon，必须用 Network 域的失败清单实证。
3. **runtime 误报队友崩溃**：`foliage` 两次被通报 "failed before it finished"，但它其实活着（最终独立完成了审计关卡）。教训：收到失败通报后**先核对文件 mtime/内容**再决定改派，不要直接把它当僵尸。
