# 交付文档 · 观战时停子系统审计 + 瞄准吸附特性（2026-09-27）

> 本批两件事：① 审计「观战时停」子系统的设计问题（**只出清单 + 证据，未改 js**）；② 实现用户要的
> 「瞄准模式（普通瞄准/开镜）与载具火力瞄准的轻度自动吸附」（**已实现，待实机验收**）。
> 工作方式同 README §4.6：改代码 → Node 沙箱回归 → 用户实机验收 → 修订。

---

## §0 一句话结论

- 时停本身的主链路（世界帧长 0 + 游戏时钟 `nowT` 同速冻结 + 观察者例外）**接线是对的**，本批用
  `dev/_timestop-audit.js` 逐条量过；真正的问题在**边界**上：dt=0 注入范式让"寿命类"对象永不回收
  （观战者弹药无限 ⇒ 开着时停按住扳机就是线性增长）、命中结算在冻结期间照常发生（炮弹每帧仍以
  0.5m 前瞻重跑判定，能"隔空引爆"活人）、观战者**自己**的弹丸/巡飞弹被冻住（与"冻战场不冻观察者"
  的裁定自相矛盾）、时停状态跨"回主菜单→继续"残留、以及海战音频是唯一还在按真实时间推进的声源。
- 另有一条**已核对为阴性**（原以为会暴走）：定点发射器（火源/燃烧树/受损车烟/炮弹拖尾）在 dt=0 下
  不是"每帧一发" —— 节拍器一旦回填成正值就被冻住，90 帧内各最多多喷一帧的量。这条写进文档是为了
  避免后续有人重复怀疑。

## §1 时停问题清单（按严重度；每条都给了证据与实测数值）

证据工具：`node dev/_timestop-audit.js`（12 断言全过 = 四条现状被复现；性质见文件头：它断言**当前行为**，
修好后会变红提醒改判据）。

### P0-1 冻结点附近的伤害照常结算（炮弹每帧以 0.5m 前瞻重跑命中判定）★实测

- `15-vehicles.js:1396 updateShells(dt)`：`step = |vel|*dt`（时停下 = 0）**但** `let hitD = step + 0.5`
  —— 位置不动，前瞻 0.5m 的命中射线每帧照跑。实测：一发**静止**炮弹放在靶兵身前 0.4m，
  `updateShells(0)` 跑 3 帧 ⇒ 靶兵掉 404 血、炮弹从表里摘除（即"冻结期间被隔空引爆"）。
- 步兵更直接：`fireBullet` 是 hitscan（`13-combat` 立即 `raySoldiers` + `damage`），时停下玩家照常扣扳机
  ⇒ 一枪一条命，票/分/连杀/破坏统计全部照常记账（只有旗点进度与 AI 计时真的停住）。
- 影响：时停定位是"看交火的研究工具"（用户 2026-09-27 裁定"只留时停"），但当前它同时是**单方面屠杀窗口**
  （幽灵坦克主炮 CD 恒 0，见 `15c-specveh`，配合本条最强）。
- 待裁定：时停下是否**禁用玩家侧伤害**（推荐）/ 只禁用非观战连狙的伤害 / 保持现状（当作观战特权）。

### P0-2 dt=0 下"寿命类对象"永不回收 ⇒ 无上限增长 ★实测

- `08-effects.js:84 spawnTracer`：回收判据是 `traveled += 340*dt`（dt=0 ⇒ 永不到 `max`），
  `tracerPool` 也就永不回填 ⇒ **每条新弹 `new THREE.Mesh`**。实测：120 次开火 → `tracers` 0→120、
  空闲池 0→0（线性、无上限）。
- `15-vehicles.js:1396 updateShells` 的 `s.life -= dt` 同理：60 发炮弹全部常驻（实测 `shells` 1→61），
  且每发带一次拖尾喷射 ⇒ 实测 60 发留下 **120 颗永不衰减的粒子**（粒子池上限 280）。
- 手雷 `nades`（`fuse -= dt`）、弹壳 `casings`（有 26 上限，安全）同理。
- 触发条件极低：观战者弹药无限 + 幽灵坦克主炮无 CD + 时停里照常开火 ⇒ 开着时停按住左键就是在加对象。
- 建议（任选）：时停下**禁火**（与 P0-1 同一处开关）/ 让弹丸寿命走 `pdt`（= 把"你打出的东西"并入观察者
  例外链）/ 给 `tracers` 与 `shells` 加硬上限。

### P1-3 观察者例外漏了"你打出的弹"与"你正在制导的巡飞弹"

- 巡飞弹：`13-combat.js:454 updateLoiters(dt)` 拿的是**世界帧长**，而"操控巡飞弹时你本人就是弹体"
  ⇒ 时停下相机在弹上、弹不动 = 观察者被定住（与 22b 声明的唯一例外直接冲突）。并且 `19-input.js:76`
  规定制导期间 J/K 让位 ⇒ 一旦制导，既不能开时停也不能动。
- 观战者自己的枪弹/炮弹：射速、换弹、开镜、后坐全部走 `pdt`（真实时间），弹丸寿命走 `dt`（冻结）
  ⇒ "能打、但打出的东西冻在枪口"（P0-2 的机制侧描述）。三条口径里这一条最不自洽。
- 建议：把"玩家/观战者打出的弹丸、正在制导的巡飞弹"并入 `specTimeRideDt` 同类例外（或按 P0-1 直接禁火）。

### P1-4 时停状态跨"回主菜单 → 继续"残留 ★实测

- `SPEC_TIME.paused` 只在两处复位：换局（`22-hud:902 resetPlayerForNewMatch`）与关闭观战（`22-hud:1272`）。
  `returnToMenu()` / `resumeBattle()` / `endMatch()` 都不复位 ⇒ 实测：时停中回主菜单，再点「继 续 游 戏」，
  回来时 `paused=true`、`specTimeFrozen()=true` —— 战场仍是静止的，玩家多半已经忘了自己按过 K。
- 建议：`returnToMenu`（战局未结束那条分支）与 `endMatch` 收尾各补一次 `specTimeReset()`；或者把
  "menuHold 期间视为已解除"并让主菜单回来时显式告知。

### P1-5 海战音频是唯一按真实时间推进的战场声源 ★实测

- `20-player.js:396` 在 `updatePlayer(pdt)` 里调 `AudioSys.navalAudioTick(dt)` ⇒ 时停下收到的是 **pdt**
  （实测 0.0167，同帧世界帧长 0）。同时 `01-audio.js:602` 还有 `if(!(dt>0)) dt=1/60;` 的兜底，即使拿到 0
  也会换成一整帧。
- 后果：整片海战场静止，但发动机音色（按冻结的 rpm 持续塑形）、破水/履带周期声照常发 ⇒ 与陆战
  （`Tank/NavalCraft.update` 内的音频塑形随 dt 停）不一致，"冻结整个战场"的观感被破坏。
- 建议：`navalAudioTick` 改吃世界帧长（或加"时停即静音"一支）。

### P2-6 没有常驻的时停指示（`specTimeStatus` 是死代码）

- `22b-speclayer.js:186 specTimeStatus()` 注释写着"HUD/探针"，全仓无人调用（只有 dev 探针）。
  切换时只有一次 `showScorePop`，长时停/中途按 Esc 回来之后没有"我现在停着"的确定读数。
- 建议：HUD 上加一枚常驻小胶囊（复用现成的读数单源），与 `SpecLayer` 的 J 指示同排。

### P2-7 结构性：`dt=0 注入` 范式本身的代价（建议本轮不动，列为长期项）

- 现状：主循环把 26 个 `update*` 分成 dt / pdt / vdt 三档，时停 = 给世界档喂 0。因此**每个系统都必须
  自己 dt=0 安全**：本仓只有 `15d-naval` 一家显式早退（`NavalCraft.update` 的 `if(!(dt>0)) return;`，
  2026-09-27I 修的那次就是因为旧版 `if(!(dt>0)) dt=1/60;` 把守卫架空了）。
- 建议方向：主循环加一个**显式 frozen 分支**（只跑观察者链 + 渲染），世界更新整块跳过 —— 这样
  寿命类对象、发射器、命中管线都自然停住，P0-1/P0-2/P1-3 的机制侧原因一次性消掉。

### §1 附：已核对为阴性（避免重复怀疑）

- 定点发射器"每帧一发"：**否**。实测 90 帧 dt=0：火源 +3 颗、炮弹拖尾 +2 颗、燃烧树 0 颗（节拍器
  `acc=0.0828` / `trail=0.05` 都是正值，已被冻住）；插进去"想定住看"的 20 颗粒子全在。
- `nowOff` 记账（世界时钟与 dt 同速冻结）无重复计数风险：暂停/结算/菜单走单独分支，两者互斥。
- 观战者例外在**坦克/战机/舰艇/幽灵坦克**四类座驾上成立（`specRide` 单源 + `vdt` 逐台判定），
  固定炮位（MG/AT/AA/迫击炮/岸防炮）的玩家侧节奏本来就在 `20a-seats` 的 pdt 链上，能动。

## §2 瞄准吸附（已实现，待实机验收）

### 需求（用户原话）

> 我希望给瞄准模式（包括开镜和普通瞄准）和载具火力瞄准增加一个轻度的自动吸附。

### 落地口径

- **单源**：`js/13-combat.js` 的 `AIM_PROFILES` / `aimAssistTier()` / `aimAssistDir(origin,dir,profile,opt)`
  —— 只有这一处判强度与挑目标；所有调用点只负责"在扣扳机那一帧把出膛方向交给它"。
- **只掰"差一点打中"的那一枪**：逐目标先算角半径 `rAng`（本体在准星上占多宽），只有弹道**擦不到本体**
  （`over = ang - rAng > 0`）且擦出距离 ≤ 本档容差 `cone` 才动手；**已经指着本体的一概不动**
  ⇒ "起点 → 准星命中点"这条既有契约在"已命中"时逐字保持（第三人称准星=落点 / 打腿就是打腿，
  不会被抬到胸口）。这一条同时保住了 `dev/verify-specthird` T6 的口径（实测 58/58）。
- **掰角** = `(over + 0.35·rAng) × k`，两道夹：不得越过目标中心（≤ ang）、不超过硬上限 `cap`
  ⇒ 目标位置 = 落进本体 35% 深（"近失误变命中"，不是"边缘蹭一下"），任何情况下看不出弹道拐弯。
- **遮挡检查**：一次世界射线（目标前 0.6m 内有碰撞体 ⇒ 不吸）+ 一次人体射线（沿该射线第一个被打中的
  必须就是它 ⇒ 队友/别人挡在前面不吸）。**吸附绝不制造"打墙/打队友"**。
- **谁吃吸附**：只有玩家侧链路（判据是调用点，不是运行时猜）——步兵枪弹与火箭筒（`20-player playerShoot`
  两处，含观战连狙）、坦克主炮与同轴机枪、固定 MG、反坦克炮、防空炮、岸防炮、舰炮主炮与并列机炮
  （`20a-seats` 八处）、战机航炮（`16-aircraft fireMGBurst` 的 `shooter===player` 分支，AI 机不吃）。
  曲射/面杀伤不接：迫击炮、巡飞弹、航弹、鱼雷。
- **档位**：`SETTINGS.aim` = 0 关 / 1 轻度（默认）/ 2 标准，游戏设置里新增「瞄准吸附」一行（关/轻度/标准），
  落 `sf_aim`，**改档即时生效**（开火时现读，不需 reload）。关档时 `aimAssistDir` 原样返回入参引用
  （零分配、零行为漂移）。
- **可观测**：只读视图 `AIM_ASSIST`（tier/shots/assisted/blocked/lastBend/lastKind/lastTarget）
  —— 控制台敲 `AIM_ASSIST` 就能当场确认它在起作用。
- **数值**（容差 `cone` 是"擦出距离"，不是"与目标中心的夹角"，所以大目标天然窗口更宽）：

  | 档 | cone | k | cap | range |
  |---|---|---|---|---|
  | hip 普通瞄准 | 1.6° | 0.85 | 1.3° | 170m |
  | ads 开镜 | 2.2° | 1.00 | 1.8° | 240m |
  | mg 机枪/航炮 | 1.5° | 0.80 | 1.1° | 210m |
  | heavy 直瞄重火力 | 3.0° | 0.90 | 2.0° | 360m |
  | air 对空 | 3.4° | 0.95 | 2.2° | 360m |

  档位再乘：容差 ×{1.00, 1.25}、掰角 ×{0.85, 1.15}（轻度/标准）。

### 验收（`node dev/verify-aimassist.js`，**40 断言 0 失败**；连跑 8 次全绿）

- T1 单源/关档零漂移（关档返回同一对象引用）；非法档位回落"关"。
- T2 ★ 60m 近失误（擦出 0.07°）从"打不中"变"命中"：**真实伤害入口**（吸附弹掉血 32.7 / 原始弹一点不掉）+
  **真链**（`playerFireTick` → `playerShoot` → `fireBullet`：捕获真出膛方向 + ≤10 枪内命中）。
- T3 ★ 三条阴性对照全不吸：隔墙（`addBoxCollider` 造实墙）/ 队友站在弹道上（人体遮挡）/ 15° 大偏；
  另加"贴脸 1.2m 内不做"。
- T4 档位单调：开镜 > 普通瞄准，标准 > 轻度；硬上限生效（最大掰角 0.95° ≤ cap 2.25°）。
- T5 ★ 载具火力真链三条：坦克主炮 120m 上真失误 1.8° → 掰进车体（1.04° < 车角半径 1.24°），
  **关档时出膛方向与炮轴逐位一致**；战机航炮（捕获真出膛方向）玩家机被掰 0.5°→0.15-0.35°、AI 机逐位不变；
  固定重机枪座（`updatePlayerMG` 真链）同样被掰。选点带自检重试（地形遮挡会被如实报成"没找到泊位"）。
- T6 只读视图计数与实际一致（大偏只记 `shots` 不记 `assisted`）。
- T7 静态接线清单 + **赋值目标可重写扫描**（`const dir=` 这种错静态子串看不见、只在扣扳机那一刻炸）。
- 相关既有探针：`verify-specthird` 58/58（含第三人称"弹道严格经过准星命中点"，吸附只在**已命中**时不动它）。

### 本批"首跑红"的定位记录（3 条；第 1 条是产品缺陷，后两条是探针自身脆弱）

1. **产品缺陷（已修）**：`verify-specthird` T1/T2/T6/T9 报 `TypeError: Assignment to constant variable.`
   （`20-player.js:797`，另发现 `20a-seats` 固定机枪座同款）⇒ 我在 `playerShoot` / `updatePlayerMG` 里把 `dir`
   当可重赋值变量用，而它是 `const`。**教训：探针覆盖不到的接线点，既有探针会替你抓到** ——
   我自己的 T2 当时只直调 `fireBullet`，没走 `playerShoot`；修 `let` 之后**补了真链断言**并新增 T7 的赋值目标扫描。
2. **探针脆弱（已修）**：`verify-specthird` T6 首轮报"弹道垂距 0.042m" ⇒ 那是吸附**旧语义**（按"与目标中心的夹角"
   收容，于是瞄着队友腿部会被抬到胸口）踩到准星契约；改成"只处理擦不到本体的那一枪"后归零（58/58）。
3. **探针脆弱（已修，本轮收敛过程）**：自建 T5/T2 一度偶发——
   ① 追踪弹是 **1/(def.tracer) 概率生成**的（`tracer:2` ⇒ 50%），不能当判据 ⇒ 改判 **捕获真出膛方向**
   （`fireBullet` 是唯一出膛口，AI 与玩家共用）+ hp 只作"多枪预算"旁证；
   ② **随机散布**会把"已吸正"的方向又抖出去（机枪 ±0.63°）⇒ 判据压在"方向"上，并把随机源归零
   （`Math.random=()=>0.5`；`rand` 是 `const`，只能从源头压 —— 首版直接给 `rand` 赋新值当场报了
   `Assignment to constant variable`）；
   ③ 载具链的通视检查原先只验 −Z（坦克炮塔 `aimDir` 是 **+Z**）且不含"炮口在车体前 4.35m"那一段 ⇒
   改为 ±Z 双验 + 跨度外扩 8m + 泊位**自检重试**（掰不动就换点，避免把地形遮挡误报成"没接吸附"）。
