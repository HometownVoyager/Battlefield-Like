## 二、枯树/椰树倒伏：实现

### 2.1 旧行为（缺陷）

`04b-fire.explosionFlora` 对植被分两档：

- `kind==='tree'`（乔木，实例批）→ 近距 `treeFall`（**立即向背离爆心方向翻倒**）、中距累积 `dmg`，两次才倒；
- **其余全部**（灌木/蕨丛/树篱/竹丛/**枯树 `dead`**/**椰树 `palm`**）→ `d<radius*0.85` 直接 `vanishFlora`。

于是枯树与椰树"被炸到就是原地冒一股土然后消失"，没有乔木那种**向爆心反方向倒下**的机制 —— 用户实机一眼看出。

### 2.2 新口径（三类同规）

`explosionFlora` 现在把 `tree` / `dead` / `palm` 并到同一支：

| 距离档 | 行为 |
|---|---|
| `d < radius*0.75+0.9` | **立即倒伏**，倒向 = 爆心 → 株心 的单位向量（±0.5m 抖动，与乔木逐字同式） |
| `d < radius+2.6` | `dmg += 1`；`dmg >= 2`（第二次爆炸）才倒伏（乔木原有口径） |
| 更远 | 不响应 |

> 覆盖面核对：旧"炸没"半径 `0.85·R` 与新的"立即倒伏"半径 `0.75·R+0.9` 在常用爆炸半径下**前者更小**（R=3.5 时 2.98 < 3.53；R=5 时 4.25 < 4.65；R=8 时 6.8 < 6.9），
> 即"原来会被炸没的枯树/椰树，现在一律改为倒伏"，没有留下"既不倒也不消失"的空档。

### 2.3 实现要点（为什么这样写）

1. **姿态写在哪**：这两类是**对象式**植被（`05b-props`：枯树 2 件独立网格 / 椰树 1 个 `Group`），不在 `TREE_IM` 实例批里。
   乔木走 `treeInstanceMatrices`（写 `InstancedMesh.setMatrixAt`），本批新增 `floraObjMatrices`（写各网格自身的 `position` / `quaternion`），
   **旋转公式与角度曲线与乔木逐字同源**（绕根部水平轴 `(dz,0,-dx)` 的 Rodrigues 展开 + `0.75k²+0.25k` 角加速 + 触地回弹震荡）。
2. **四元数按分量手算**（`R ⊗ q0` Hamilton 积）：沙箱 THREE 桩没有 `clone/copy/set`（`verify-fire` 的 `Quat` 甚至把
   `setFromAxisAngle/premultiply` 做成空转），若依赖实例方法，倒伏在探针里就是"字段写了、几何没动"。
   手算 + `position.set` 让**同一段代码在真 three 与桩里都真的把树转过去**（真 three 侧另有 §三-② 的独立取证）。
3. **倒伏曲线/扬尘/沉入复用乔木那一套**：同一个 `FALLING` 列表（`f.obj=true` 分流姿态写入）、同一个 `treeFallImpact`
   （扬尘半径改取 `f.s`，乔木仍取 `tr.s`，乔木行为零变化）、沉入改走 `08-effects.queueSink`（对象网格版，与
   `vanishFlora` 已用的同一条路），停留/下沉时长与乔木一致（**16~22s 停留 + 3.6s 沉入**）。
4. **碰撞体即杀**：`killCyl(rec.cyl)`（与乔木同规：**不**触发寻路重建，残干占位留到下次 rebake —— 见 `treeFall` 既有注释）。
5. **株高来源**：对象式植被没有 `s` 字段 ⇒ 取 `cyl.y1-cyl.y0`（椰树 6.6~12m / 枯树 3.4m），折算等效 `s=clamp(h/4,0.5,2)`
   用于倒伏时长与扬尘半径（椰树倒得比枯树慢，符合观感）。
6. **防重复登记**（三处补门，都是"同一批网格挂两个沉入任务 ⇒ y 基线互踩会跳变"的同类根因）：
   - `explosionFlora`：`if(!rec.alive) continue`（已倒伏株不再响应后续爆炸）；
   - `floraCrushTank`：`dead` 分支与末尾 `else if(d<2.0)` 分支都加 `rec.alive===false` 早退（坦克碾过倒伏残骸不再二次登记）；
   - 火焰烧尽路径：`if(!rec.dead && rec.alive!==false && rec.kind!=='tree')`（倒伏中的枯树/椰树不再被"烧尽"顺手炸没）。

### 2.4 刻意不改（如实记录）

| 项 | 现状 | 理由 |
|---|---|---|
| **坦克碾压**枯树/椰树 | 仍是"一碰即碎/碾没"（`vanishFlora`） | 用户本次只点了"被炸到"；`floraCrushTank` 的枯树"一碰即碎"是 2026-09-12 批次明写的口径，不顺手改 |
| **火烧**枯树/椰树 | 仍走"烧尽 → 原地消失" | 同上（火不是爆炸）；且火焰路径按 3m 格批量处理，逐株倒伏会牵动 `updateFires` 的批处理节奏 |
| 倒伏后的**通行/挡弹** | 残干不再有碰撞（与乔木一致） | 倒树躺地不挡路是本项目既有语义（"倒树不挡路"注释在 `treeFall` 里） |
| 中距（`0.75R+0.9 ~ R+2.6`）需**两次**爆炸才倒 | 与乔木同 | 保持"三类同规"，不为这两类另立阈值 |

## 六、待实机验收（请按现象看）

1. **椰树**（塔拉瓦环礁，最好在椰林营区/滩头）：用手雷/火箭筒/坦克炮/航弹在椰树旁炸 ⇒ 树应**立刻朝远离爆点的一侧翻倒**（1~2 秒倒完、带扬尘），
   不是"原地冒土消失"；倒下的椰冠会在地上躺十几秒后沉入地下。
2. **枯树**（柏林/莫斯科/诺曼底/滇缅的枯木）：同上；**坦克直接开过去**仍是"一碰即碎"（这条没改）。
3. **连炸**：同一株再炸一次不会有异常（不抖、不瞬移、不二次沉入）。
4. **中距**：站在树旁 7~8m 处炸一次（爆炸半径 5 的武器）⇒ 第一次只是"树晃一下没倒"，**第二次**才倒（与乔木一致）。
5. **换局/回主菜单**：把椰树/枯树炸倒 → 打完这一局回主界面 → 主菜单航拍里的椰林/枯木应是**直立完好**的（不是歪的、不是躺在地上）；
   就地开新一局同样应是直立完好的。
6. **性能**：连炸一片椰林（10~20 株同时倒）不应有明显掉帧。
