## 一. D1 被当空击毁的飞机浮空固定（重立案 → ☑ 关闭）

**用户原报**：「被当空击毁的飞机会浮空固定，需要修复。」
**决定性取证（用户）**：「在观战模式下，即使没有开过时停也没有召唤过幽灵坦克，也总是会出现浮空现象。」

**病根（实锤，在观战信息层，与击落方式/时停无关）**：
- 09-28B 批已把 `die()` 改成"隐藏本体+挂残骸"原子化先行，但**观战期**击毁仍走不通：
  22b-speclayer 的名牌 Sprite 挂进 `plane.grp`（`specTagOf: h.host.add(t)`），且
  `t.userData.host = h.host` —— **自引用环**（userData.host 指向自己的祖先 grp）。
- `die()` 里的 `grp.clone()` → THREE `Object3D.copy` 对 userData 做 `JSON.parse(JSON.stringify(...))`
  （r125+ 行为）→ 抛 "Converting circular structure to JSON" → 异常打断在 `alive=false` 与
  `grp.visible=false` **之间** ⇒ 飞机已死、永不更新、本体还挂在天上，残骸未挂无坠落。
- 三证互锁：「一段时间后消失」= die() 的 35~48s 死亡重生计时把本体清走，与坠落无关；
  平时（非观战）不复现，因名牌只在观战期挂载；此前两轮探针"全绿"是**判据盲区里的绿**
  （游戏实载 41 个脚本、探针只载 39 个，`22b-speclayer.js`/`19b-gamepad.js` 从未进沙箱）。

**改动**：
- `js/22b-speclayer.js`：删除 `t.userData.host=h.host`（环源，全库无读者），保留 cv/y/t 等无环字段。
- `js/16-aircraft.js`：die() 结构性加固 —— `this.grp.visible=false` 提前到 `alive=false` 之后**立即**
  执行；后续交接块（信标摘除/clone/残骸挂载/入列）整体 try/catch（`[击落] 残骸交接异常` 兜底日志）。
  即使再有任何副作用异常，本体必隐、残骸必挂，"死而不隐"从结构上不可能。

**判据**：`verify-phase2-20260928` D1-K1~K7 —— 直伤/溅射/触地/玩家座机四击落路径全过；registerKillScore/
addKillfeed/explosionFX 三处副作用投毒抛异常后单位仍原子退场；时停两态口径（dt=0 冻结、解除后落地）不误伤；
观战名牌已挂现场的击落链完整。`dev/_d1spec.js` 观战复现链：修前 die 链抛循环结构异常（红）、修后全绿。

## 二. D3 不可破坏建筑墙体/谷仓房顶材质贴图不一致（重立案 → ☑ 关闭）

**用户原报**：「全部不可破坏的建筑墙体和谷仓房顶存在严重的材质贴图不一致的问题！」
**用户形态澄清**：「各个部位明暗区别很大。」＋ **裁定：取消永久件提亮**。

**病根（两层）**：
- **层一 = B5 永久件逐盒提亮**：markPermPieces 给每块 box 单独 structMatPerm +6% 亮度 ⇒ 带门窗的墙体
  被拆成多块 box，提亮块与不提亮块同墙拼接 = 一墙两色的"拼块感"。09-28E 批的 uvRef 回写让贴图密度
  正确之后，**亮度差**成为唯一可见残差。
- **层二 = 非盒几何不归一**：uvGeo 此前只有 BoxGeometry 分支，烟囱/草垛类 Cylinder 侧面 UV 是
  三内置 0..1 直通 ⇒ 贴图密度与整墙完全不同尺度（"烟囱巨砖"）。

**改动**（`js/05-world.js`）：
- `structMatPerm(mat)` 改为直通（单源壳保留、perm 盒标记保留——T10/roofghost 判据口径不受影响）；
  24-main 启动日志同步注明"提亮已按 2026-09-28 用户裁定取消"。
- `uvGeo` 新增 CylinderGeometry/ConeGeometry 分支：侧面 u 按 `thetaLength·rMax/S`、v 按斜长
  `√(h²+(rT−rB)²)/S` 归一，端盖按 `(uv−0.5)·2r/S+0.5` 归一；侧面/顶盖/底盖分类走 `g.groups`
  （heightSegments=1 时侧面顶点也在 ±h/2 平面，按 y 分类会全误判）；仅对带 uvRef 的材质生效，
  参数键缓存防重复处理。

**判据**：`verify-phase2-20260928` D3a（全库 0 件 permTier 材质 + perm 盒标记保留 + markPermPieces 幂等）
+ D3b（淞沪丝厂砖烟囱/诺曼底谷仓草垛圆柱三向密度 vs 理论值 + uvGeo 直调 + 树皮阴性对照，双战役）。

## 三. D9 第三人称本体偶发"隐身"（随批报告 → ☑ 关闭）

**用户原报**：「有时开第三人称的时候玩家的模型不显示，像是隐身了一样。不过没有实际影响，该中弹还是中弹。」

**病根（实锤，世界还原 × 惰性常驻对象）**：`playerAvatar` 是对局中首次按 U 才 `scene.add` 的惰性常驻对象
（`playerAvatarEnsure → buildSoldierMesh`），必然不在开局快照里 ⇒ `restorePristineWorld` 的
`_wsnRestoreGraph` 把它整段摘出场景（parent=null），而模块级 `playerAvatar` 引用还在 ⇒ 下一局
`playerAvatarEnsure` 复用旧 root，每帧 `visible=true` 写在已脱离场景的节点上 = 相机正常拉到身后、
本体与枪模全不渲染；命中判定走解析几何与外观无关，所以"该中弹还是中弹"。
`clearMatchEffects` 对同类惰性对象（小队标记/玩家降落伞）均有"摘除后置空"，唯独漏了 playerAvatar。
「有时」= 上一局用过第三人称才触发。

**改动**：`js/20-player.js` 新增 `playerAvatarReset()`（摘 parent + 置空引用，下次 ensure 原地重建）；
`js/23b-worldrestore.js` 的 clearMatchEffects 按降落伞同款 typeof 守卫调用。

**判据**：`verify-phase2-20260928` D9a-c —— ensure 后在场景 → 无 reset 阴性对照复现病根现场
（还原后 root.parent===null）→ reset 后 ensure 原地重建回场景、还原后引用已被清空。

## 四. D10 观战指向线跨局全灭（顺带发现 → ☑ 关闭）

**起因**：无用户报点；D1 观战态排查顺带发现的 D9 同族缺陷。

**病根**：`specLineOf` 是 `scene.add` 的惰性对象，与 D9 本体同族——不在开局快照里，被世界还原摘出场景
（parent=null）而 `u._specLine` 引用残留 ⇒ 下一局观战所有指向线都已脱离场景，一条都画不出。
名牌挂在单位 grp 里随单位走，无此问题。

**改动**：`js/22b-speclayer.js` specLineOf 自愈——取线时 `if(!l.parent) scene.add(l)`。

**判据**：`verify-phase2-20260928` D10a-c —— 首次取用在场景 → 世界还原摘出的阴性对照 → 再取用同一线
自愈重挂 scene。
