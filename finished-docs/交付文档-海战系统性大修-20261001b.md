## 一、逐条根因与修法 (用户八条)

### ① "旗帜和旗帜周围的东西对船体严重漂移, 总是出生在海上"
- **根因甲 (已由上午批修, 本批复核)**: 铁底湾旧旗坐标换算到舰体局部是舷外 21m 悬空 (见 00-config:856 内注释); 珊瑚海写法正确。旗位绑定 `capitalFlagBind` (开局换算舰体局部) + `capitalFlagTick` (每帧跟随) 上午已接线。
- **根因乙 (本批修)**: 旗周**弹药箱**只搬网格不更新判据坐标 (见 ②)。
- **本批加固**: 探针 S2 全量断言——6 面甲板旗局部坐标全部落在各自甲板矩形内 (`capDeckIn`), 跟随偏差 <0.02m, 旗杆基高=甲板面; 阴性对照: 手工挪舰后不 tick 旗纹丝不动 (证明跟随确实由 `capitalFlagTick` 驱动, 判据非空转)。

### ② "船上的补给箱失效"
- **根因**: `capDeckPropTick` 只搬 `c.mesh.position`, **不更新 `c.x/c.z`** —— 而交互链 (`20-player tryInteract`/`updateInteractHint` 的"补充弹药"判据) 读的是 `c.x/c.z`。舰一开走, 判据坐标停在 t=0 的海面上 ⇒ 玩家明明站在箱子旁, F 补给永远不出现。
- **修法**: `capDeckPropTick` 网格与 `c.x/c.z` **同帧同账** (js/15h)。
- **判据**: S3——每个甲板箱 `capToWorld(局部)=c.x/z=mesh.position` 三者逐位一致, 箱底=甲板面。

### ③ "甲板以上的东西总是没有碰撞判定, 能直接穿过去"
- **上午批已修甲板层推出语义** (`capPushBody` 甲板层=护栏夹持, 水线层=舷侧硬墙); 本批复核 + 补齐判据: S4a 断言甲板内点 `capDeckY` 给甲板面、缘外点被夹回 `railIn` 内。
- 局部绕行 (`capLocalSolve`: 上层建筑/炮塔/烟囱/炮座盒) 与子弹遮挡 (`capitalRayQuery`) 既有接线, 探针全链 boot 验证无回归。

### ④ "船体移动的时候上面的人无法完全正常地移动, 船不像是'移动的陆地'"
- **根因 (上午批已修大半)**: `capPushBody` 旧版把甲板上的人当"撞舷侧的游泳者"弹到舷外 ⇒ 人根本站不住。本批补齐**判据**:
  - S4: `capCarryDelta` 刚体位移验证——上一帧位姿下的世界点投回当前位姿 = 同一局部点的当前世界点 (旋转+平移全对);
  - S4b: 真实链路——甲板上放一名 Bot, 手工挪舰一帧跑 `updateCapital`, 人跟着走 ≥3m 且仍在甲板矩形内。

### ⑤ "大量物体浮空, 如天线、炮塔、护栏等"
- **上午批已修** (铺面按站位表收窄 / 舷侧贴面逐件求表面 x / 舰岛骑上甲板缘 / 航母支撑裙板 / 护栏折线闭合)。本批把"浮空"固化为**常驻审计** (探针 S5):
  - 主炮塔底面 ≤ 承托面 (0/2 号塔坐进甲板; 1 号叠置塔坐在下塔顶上, 旧审计误报已纠正口径);
  - 副炮/防空座圈不得**悬**在甲板室顶/飞行甲板之上 (下沉数 cm = 坐进结构, 允许);
  - `capDeckHW` (可行走半宽) 不得超甲板半宽。4 舰全过。

### ⑥ "船之间没有碰撞判定, 会互相穿过"
- **根因**: 全库只有 `capPushCraft` (大舰推小艇) 与 15d 的艇间推挤, **大舰↔大舰没有任何分离逻辑**。
- **修法**: 新增 `capPushCap()` (js/15h)——两舰等质量各让一半, 沿**穿透更浅的轴**分离 (+5cm 余量防浮点贴合抖动), `updateCapital` 每帧调用。巡航航线擦过时边推边追踪航点, 自然错开。
- **判据**: S6——重叠检出 (阴性对照: 不调它仍重叠)、推开后两舰局部互不重叠、双方都位移。

### ⑦ "意义不明的两栖坦克在纯海战中出现, 飞机太少, 小船也有点太多"
- **修法** (00-config 战役表):
  - coral 珊瑚海: `navalN [2,4]→[0,2]` (两栖车退场——全海图没有滩头可抢; 小艇 4→2), `airN [2,2]→[4,4]`;
  - ironbottom 铁底湾: `navalN [0,4]→[0,2]`。
- **判据**: S7——navalN[0]=0 / navalN[1]≤2 / airN≥4 / 场上两栖车=0。

### ⑧ "起始界面不显示舰船, 只有一片海"
- **根因**: 大舰在 `startMatch` 才生成, 主菜单航拍 (载入期世界) 里自然是空海。
- **修法**: 大舰改为**载入期生成** (`24-main` boot 段, 在 `capturePristineWorld` 快照之前 ⇒ 舰体网格进开局快照); `startMatch`/就地重开改走 `capitalEnsureOrbat()` (已在场 ⇒ `capitalReset()` 复位+重绑甲板旗, 不重建); `retireMatchActors` 的大舰段从"摘 grp+清表"改为"复位复用"; `23b-worldrestore` 还原世界时追加 `capitalReset()` (瘫痪/炮位废损/巡航偏移不在快照里)。菜单期 `updateCapital` 照跑但**停火** (`menuHold` 守卫: 巡航/搬旗/搬运照常, AI 火控与接管不跑) ⇒ 主菜单航拍里是**编队巡航**的画面。
- **判据**: S1——boot 后 (未开局) `capitalShips.length=4`; startMatch 后仍 4 艘 (不重建); 24-main 源锚 (菜单分支调用 + 载入期生成)。

## 二、三条期望的落地

### 期望A "各个分炮塔有自己的血量, 可以上去操控, 被打坏了就不能用"

**血量链** (数值单源 `CAPITAL_SPEC.main/sec/aa.turHp`: 主炮塔 2400/2600, 副炮 320/340/320/300, 防空 200/210/200/190; 结算常量 `CAPITAL_CFG.turSpill=0.35`):
- 15g 命中盒直接带 `part:'main'|'sec'|'aa'` + `pi` 索引 (单一出处, 不靠解析名字符串);
- `takeDmg` 按 part 路由: 命中炮位的伤 (带 tur 装甲倍率) **先记进炮位自己的血量**, 同时按 `turSpill` 溢出进舰体 (打炮塔对瘫痪舰体仍有贡献); **打空 ⇒ 报废** (`_partDead`);
- **废塔不再是装甲**: 报废后的后续命中按舷侧 'hull' 装甲区全额结算;
- 报废表现: 主炮塔偏舷+炮口低垂定格 / 副炮防空管口下垂 + 焦黑材质 + AI 永不再用它 (开火函数与火控双重守卫) + 战报"「XX舰」的 40mm 博福斯 被摧毁"。

**操控链** (`player.capitalGun = {ship, type:'main'|'sec'|'aa', idx}`, null=未接管):
- 甲板上走到炮位旁 (**接管半径 `gunR=3.4m`**) 按 F 上炮; 再按 F 下炮; F 优先级: 已在炮位⇒下炮 → 炮位半径内⇒上炮 → 舷缘跳海;
- 操控 = **视角即炮口**: 鼠标视角 → 座圈回转/俯仰 (回转速率 `gunSlew`: 主炮 0.30 液压重炮 / 副炮 1.4 / 防空 2.0 rad·s⁻¹; 俯仰钳 `gunPitch`), 炮口没转到位不出弹 (与 AI 同门限 = "人在操炮"的手感);
- 开火走与 AI **完全相同**的 `fireMainSalvo/fireSecondary/fireAA` 单源 (同散布同弹速同冷却, 无任何制导; 主炮=整塔齐射, 弹道按视线交点解算); 击杀/命中归因随人 (`_shooter` 按接管态返回 player);
- AI 不碰玩家接管的炮位 (`aiTick` 守卫); 接管中被炸废 ⇒ 就地弹人 (`_partDead`→`capGunRelease(true)`);
- 站位钉在炮位锚点 (主炮=炮座圈侧旁甲板, 副炮/防空=座圈下), 舰动跟着走; 提示行/指纹位/VM 隐藏/第三人称 fov 全部接线 (三处逐级同序)。
- **判据**: S8 (part 路由/溢出/报废守卫/废塔透传/副炮同律 + 阴性对照"无 part 命中不碰炮塔血量") + S8b (上炮/钉位/视角驱动座圈/炮废弹人)。

### 期望B "船体被打坏了标识变灰, 变为无阵营的陆地, 无法作为重生点, 也无法被占领"
- `cripple()` 改版: 甲板旗点就地**中立化** (owner=-1 / 进度清零 / `drawFlagTex` 重绘灰旗 / 旗面半桅); 瘫舰横倾+焦黑+票数扣减既有保留;
- **`capFlagActive(f)` 单源** (js/15h): 所在大舰瘫痪 ⇒ 旗无效。消费方全接: `21-match updateFlags` (退出占领结算, 圈里有人也不动) / `flagsLostOf`+占满全旗判定 (瘫旗不计入 ⇒ 不会卡死胜负条件) / `23-deploy buildSpawnList` (不出现在部署列表) / `drawDeployMap` (灰底斜杠) / `14-bots pickObjective` (Bot 目标跳过);
- **基地回退**: `capBasePos` 跳过瘫痪舰——本队基地舰瘫 ⇒ 回退本队另一艘还在巡航的大舰 (如 bb_us 瘫 ⇒ 基地跟 cv_us); 全瘫 ⇒ 静态兜底;
- 旧裁定"甲板照走照占/旗点继续可争"作废 (00-config CAPITAL_SPEC 头注释已改写); 瘫舰本身仍可站立/通行 (无阵营的陆地)。
- **判据**: S9——瘫后旗中立/`capFlagActive`=false/圈里放人 `updateFlags` 不改归属/胜负豁免计数正确/基地回退到 CV/巡航舰的旗不受累。

### 期望C "大炮巨舰互轰和飞机空战加轰炸同时进行, 航母、飞机、航弹应该有足够的影响力"
- **鱼雷穿舰修复 (实锤)**: `capitalTorpedoHit` 首版**全库零调用**——鱼雷从 152m 舰体正中穿过去。接线到 `15d updateTorpedoes` (小艇没接住再问大舰; 判定/进水/战果全在 15h)。
- **航弹哑弹修复 (实锤)**: `nadeStep` 的载具触发圈只查 tanks/trucks ⇒ 航弹穿过飞行甲板直落海里被"入水哑火"吃掉。补: 小艇 2.6m 触发圈 + **大舰甲板接触** (`capDeckOf` 判舰体矩形内 + 降到甲板面+2.6 ⇒ 在甲板面高度引爆; 甲板接触优先于入水哑火)。
- **飞机对舰 (AI)**: 巡逻目标评分补 `capitalShips` (只在**挂弹时**点名大舰——机炮啃不动装甲; 评分 200 高于坦克 150) 与 `navalCraft` (扫射/轰炸皆可); 大舰俯冲瞄准点抬到甲板面 (旧版追水线下 6m 的舰心会把飞机带进海里); 塔拉瓦沿岸小艇从此也在空袭范围内。
- **飞机撞水线**: `planeFloorY()` 单源 (地形/水面取高)——旧版撞地线=海床+2 ⇒ 全海图飞机贴浪底飞不炸。撞地线/地形规避/接管 AGL/扫射进入线六处全部换用。
- **编制** (见 ⑦): 每队 4 架舰载机, 机型 0/1 交替 = 半数是挂 3 弹的攻击机; 航母瘫痪 ⇒ 停放舰载机**紧急弹射离舰**。
- **判据**: S10a (鱼雷直调+在途接线, 舰掉血且雷被消耗) / S10b (源锚) / S10c (`planeFloorY(0,0)=0` 而非 −26)。
