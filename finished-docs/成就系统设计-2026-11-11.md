## 1. 总体架构裁定

**R1 轮询账，不做侵入式事件钩**。成就进度不往火/破坏/死亡路径里插桩，而是新模块持一张
"开局普查账"，由主循环低频轮询（0.5s）按各系统的**现存状态字段**复核进度。
理由：①烧毁/破坏/倒伏的事件收口分散在 5+ 处，插桩面大、探针暴露面大；②轮询判据
（FUEL≤0.05 / tr.fall / rec.dead / g.dead / b.dead / c.dead / w.alive===false）全部是
各系统的**既有权威状态位**，无新增语义；③对未加载新文件的探针零影响（见 R8）。

**R2 普查账按"一局内世界状态"计，不做击杀归因**。任何来源（玩家/Bot/环境炮击/油桶链）
造成的烧毁/破坏/倒伏都推进进度；观战期发生的事件不计入（见 R5）。
理由：归因制存在数学不可能——草原的环境炮击犁地点燃麦田（igniteArea null 归因）、
Bot 载具残骸火、钢水包殉爆都会替玩家"烧掉"格子，归因制下这些格子永久死库存，
成就在该局直接不可完成。状态制下"全部可以烧掉的东西"=终局时不再有未烧的可燃物，
与「在一局游戏中烧掉全部…」的语义一致，且玩家仍是唯一能系统性纵火全图的主体。

**R3 普查单位口径**（开局 startMatch 时快照，`dead/alive` 已死的剔除）：

| 账 | 单位 | 枚举源 | 达成判据 |
|---|---|---|---|
| 可燃格 | 燃料格 ci（开局 FUEL>0.05） | FUEL 全表扫描 | FUEL[ci]<=0.05 |
| 树 | FLORA_HASH 中 kind∈{tree,willow,palm,dead} 且存活的记录 | FLORA_HASH 全表 | 烧尽：charred===true‖dead===true；倒伏：fall!=null‖dead===true‖alive===false |
| 植被对象 | kind∈{bush,fern,hedge,bamboo} | 同上 | rec.dead===true‖rec.alive===false |
| 结构组 | DESTRUCTIBLES 中 !dead 的组（构建期预塌天然排除） | DESTRUCTIBLES | g.dead===true |
| 掩体 props | BOXES 中 b.crush 且 !b.flora 且 !b.dead | BOXES | b.dead===true |
| 油桶 | CYLS 中 explosive 且 !dead | CYLS | c.dead===true |
| 铁丝网 | wires 中 alive!==false | wires | w.alive===false |

排除项（明确不在任何账内）：载具（可燃可毁但会重生，非场景物）、屋顶链
（承重墙组的坍塌后果，不独立计）、玩家局内新建工事（丧尸模式 ZFORT 注册的新组
不在开局快照里，天然排除）、草垛（现版无 fuelAdd，本就不"可以烧掉"，不改它）。

## 6. 实机反馈批增补（2026-11-11 晚，用户实测后指令）

用户实报：**「达成一次成就之后就会导致成就不停跳出来」** + **「达成成就的弹出框显示过于
简陋，需要多加料」**，并改令三事：观战可达成（R5 已改）、设置页加「清除游戏数据」、
数据统计加终身累计六项。

**6.1 连跳 bug 诊断与双保险**。首版弹框有两处实锤缺陷：①`achToastPump` 缺
`ACH_TOAST_Q.shift()` 行（裸名 `name` 在浏览器静默解析成 `window.name` 空串 ⇒ 成就名恒空，
弹框只剩「成就已达成 🏆」光秃一条，多条排队时看起来是同一条在反复跳）；②同帧多成就
（烧尽最后一格常同时满足 yiling_fire + better_yiling + bear_king）排队逐条播，旧行读下
像是"不停跳出来"。修复：`shift` 补回 + 弹框加料后每条内容可辨；另加**结构性双保险**
`ACH_TOASTED` 会话闩（`achUnlock` 在 `ACH_STATE[id]` 永久账守卫之后再查闩——即使存档被
外力清空，同一成就本会话也只弹一次），`ACH.resetAll()` 供清除游戏数据同步清闩。

**6.2 弹框加料 + 位置双形制（R7 已改写）**。DOM：`.achTRibbon`（金带头章「成就已达成」）
+ `.achTBody`（🏆 图标脉动 `achPulse` + 名称/描述/进度 `.achTMain` 三行）+ `::before`
高光扫过；进度行单源 `achProgText(kind)`（弹框与成就面板共用）。位置 `sf_ach_pos`

CSS `#achToast.posTR`（右上竖卡）/`#achToast.posBC`（正下横匾）双形制分形。

**6.3 清除游戏数据**。`clearGameData()`（21-match）：枚举 localStorage 清
`sf_rec_*`（各图战绩）/`sf_best_*`（旧版最高分兼容键）/`sf_ach`/`sf_stats` 四类，
**设置类键（sf_lang/sf_qual/sf_aim/…）一律保留**；返回清除条数。设置页 #mSet 新增
「数据」区 + `clearDataBtn` 两段式确认（首点武装 5s 变红「⚠ 再点一次确认清除」，
再点执行，回显「✓ 已清除…」后复位；`.optBtn.danger` 武装态样式）。成就内存账与弹框闩
经 `ACH.resetAll()` 同步清（重达成可再弹）。沙箱 bootstub 与探针 boot 的 localStorage 桩
补 `length`/`key(i)` 枚举能力（clearGameData 依赖遍历）。

**6.4 数据统计终身累计（`sf_stats`）**。单源 21-match：`statsLoad/LIFE_STATS/statsSave/
statsAccumulate(winner)`。六项：击毁载具 `veh` / 击杀 `kills` / 死亡 `deaths` /

`.lifeGrid`，22-hud renderRecordsPanel 每次打开重算）。
