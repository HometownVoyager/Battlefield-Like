## 二、修复清单

### A. 致命: js/20-player.js 重复声明 cmdLock

- 现象: 同一 updatePlayer 作用域内两条 const cmdLock, SyntaxError 令整个 20-player.js 解析失败
  (46 个脚本里排第 40 位, 文件一挂游戏直接白屏, 不是"某功能坏了"而是"整个游戏起不来")。
- 修复: 保留函数头那条单源声明 (座位分派段的定身判据), 删除移动块里的重复行; 定身判据改为
  "只算一次、全函数复用", 并补注释说明判据来源与 node --check 判据。

### B. 底图烘焙卡顿根治 (开图/进布势当帧整帧僵住)

- 现象: 点指挥官卡进布势 / 右键开指挥地图, 画面僵住一下再跳出来。实测单次同步烘焙:
  诺曼底 105ms / 斯大林格勒 135ms / 塔拉瓦 271ms / 库尔斯克 473ms / 滇缅 695ms / 百团黄土 733ms。
- 根因: 不是采样密度, 而是"单帧干完全部活" —— 且 heightAt 单点价格随地形特征数差 13 倍
  (诺曼底 2.5us / 百团黄土 33.8us, 黄土要逐段算 5 条沟壑折线 + 10 条坡道 + 塬面/峁/渡台)。
  所以**任何固定像素步进都治不了**: 上一轮把步进 4px 调到 6px 只救了诺曼底, 黄土仍 0.48s。
- 修复: 预算式增量烘焙。CMD._bj 作业对象记续算游标, cmdBakeAdvance(CMD_BAKE_BUDGET_MS=8)
  每帧只推进 8ms, 地形色带逐行推进, 道路/建筑/废墟钩子在行跑完后一次性收尾;
  cmdFrameTick 每帧推进 (地图没开也推 = 部署页期间预热); cmdMapDraw 起作业/贴现成底图,
  生成期间画 "底图生成中…" 占位 + 进度条。
- 结果: **最坏单帧 754ms → 12.8ms (约 1/59)**; 视觉产物与旧写逐像素一致 (步进仍 6px, 画法没改),
  变的只是"什么时候画完", 不是"画成什么样"。
- 探针新增两条断言并在负控下验证报红: 分帧行为 (作业期间 bake 仍空 / 逐帧推进 / 落账清作业)
  与单帧预算封顶。负控实测: 去掉预算早退后单帧最坏回到 286ms, 精确复现原病。

## 三、本轮踩到的两个值得记录的坑

1. 子代理改 js/20-player.js 后没有跑 node --check 就收工, 留下致命 SyntaxError。
   教训: 凡是改了函数作用域内的声明, 收工前必须 node --check (本仓探针会因此整链白屏,
   看起来像"探针挂了"而真相是"游戏挂了", 两者排查方向完全不同)。
2. 沙箱探针的 canvas 桩 (mk2d) 返回 Proxy 真值, 所以 `cv.getContext("2d")||null` 在沙箱里
   **不**走"无 2d 上下文"支 —— 探针与浏览器走的是同一条渲染路径。这是好事 (测的就是线上路),
   但写探针时不能假设"沙箱没有 2d 上下文"。
