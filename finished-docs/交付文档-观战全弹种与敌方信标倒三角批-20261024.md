## ① 敌机/敌坦克信标改倒三角（友方保持正三角）

**改动**：`js/16-aircraft.js`（飞机信标）与 `js/15-vehicles.js`（坦克信标）的 canvas 绘制各分两支；新增单源判据 `js/00-config.js beaconInverted(team)`。

- 判据：`beaconInverted(team) = (player.team 有效) ? team!==player.team : (team===1)`——敌我是**相对玩家队伍**的。真实对局里 `startGame()` 先赋 `player.team=SETTINGS.team`、后 `startMatch()` 落载具（22-hud startGame 首段），建模期判定安全；裸调（沙箱）兜底按「玩家=0 队」。

- **不动的部分**：队色（TEAM_COL+白描边）、位高（飞机 3.4 / 坦克 3.8）、尺寸（4m / 2.4m）、depthTest=false、脉动式（0.6+0.4·sin）、`update` 顶部的 alive 显隐单行——§一.71① 的全部产物契约原样保留（verify-vehmodels / verify-batch-20261024e 仍绿）。
- 玩家换队（选边）后判据自动翻转：1 队视角下 0 队载具显示倒三角。

**病根**：`22-hud updateNadeArc` 的显示条件里有一道 `!player.spectator`——观战者举雷时整套预演（弹道点串/贴地杀伤圈/精确弹着点/预计投掷距离+圈内人数提示）被整体挡死。

## ④ 被烧毁的植物先变黑炭色再消失

**病根（两条）**：
1. 烧尽路径（updateFires 情况 B）与 `vanishFlora` 的染色守卫是 `im.instanceColor` 非空才 `setColorAt`——而草丛/庄稼（BURN_INST）与灌木（BUSH_IM）实例批**从未初始化 instanceColor** ⇒ 守卫恒假，烧尽只沉入、不变黑（用户实报）。
2. 语义混线：`vanishFlora(rec,blasted)` 把「染焦黑」挂在 `!blasted` 上——碾碎枯树/碾没灌木也走黑炭，被炸的反而干净。

**改动**（全在 `js/04b-fire.js` + `js/05b-props.js`）：
1. 新 `instColorInit(im)`：建模期对实例批做**全白** instanceColor 初始化（乘法恒等项 ⇒ 观感零变化）。四处生效：`registerBurnableInst`（草丛/庄稼）、`flushBushes`（灌木）、`flushTreeBatch`（树干，05b）。放建模期而不是烧毁瞬间，还免去运行中 instanceColor null→非null 触发该材质 getProgram 重编译的一次性卡顿。
2. `vanishFlora(rec,blasted,charred)`：染焦黑改为显式 `charred` 参数。**只有火烧进来的消亡**（烧尽调用点 `vanishFlora(rec,false,true)`）才染黑——灌木/草丛/庄稼走实例色 `0x241d16`（与树干同一 _charCol），蕨丛/树篱/枯树等 mesh 类走 `_charredFloraMat` 材质；碾压/炸没路径不传 charred，不再误挂黑炭语义。
3. 既有沉入链不动：染黑 → 停留 3.5~8s → 沉入 → 零矩阵消失 =「变黑**再**消失」。树「烧尽=树冠消失+树干焦黑留在原地」的已验收行为原样。
4. **顺手修**：`_charredFloraMat` 从 `window._xxx` 挂载收编为模块级单例（名字不变，verify-fixes 的字符串断言仍命中）。起因：裸 Node 沙箱 `verify-fire.js` 没有全局 `window`，其烧尽路径一进 mesh 焦黑分支就 `ReferenceError: window is not defined` 整探针崩溃——**A/B 实证为预存崩**（把本批 charred 语义撤回 `!blasted` 旧口径，同一行同一错崩）；修复后 verify-fire 跑通全程，暴露被崩溃掩盖的 3 条预存断言红（树冠着火后未倒伏 / 倒伏后树干碰撞体未移除 / 火焰每跳伤害 2.34），**A/B 实证同为预存**（撤本批语义后三条红与数值逐位相同：r=0.5387416211189702、2.3400000000000003）。红账形态由"崩溃"转为"3 条断言红"，留待后续批次消账。
