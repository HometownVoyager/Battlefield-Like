## 2. 病根（动码前钉死，均带文件位置）

1. **自雷**：`19-input.js`(KeyG/Digit3/4/6) 举雷时写 `player.nadeFuse=3.8`，`20-player.js` 逐帧
   `p.nadeFuse-=dt`，到 0 **在自己脚下 `explodeAt(p.pos+1m, p)`**（旧"烧引信自爆"口径）。而"按住 = 举雷
   瞄准"是本游戏**唯一**的投掷瞄准动作 ⇒ 举满 3.8s 必炸自己，无处可躲。
2. **预演是一条线段**（三条根因叠加）：
   - ① `releaseNade`（18-game）与 `updateNadeArc`（22-hud）**各写一遍** `camera.position + camForward()`
     作为出手点/方向 —— 起点落在**相机轴线**上 ⇒ 整条弹道都在"相机轴线所在的竖直平面"内 ⇒ 投影到屏幕
     **必然是一条穿过准星的直线**（数学必然，与弧线高低无关）；
   - ② 初速剖面是平直快球（水平 26 m/s、上抛仅 2.4 m/s）：30m 只抬高 0.3m，弧线本来就几乎没弧度；
   - ③ 第三人称相机后拉后起点仍在相机轴线上 ⇒ 两视角看到的形状**一模一样**（用户附图即此）。
3. **只按空炸显示**：`nadeStep` 旧版第一行 `if(st.fuse<=0) return 'blow'` = 引信到点**直接引爆**（空炸）；
   而举雷期间引信在烧 ⇒ 举一会儿之后预演算出的第一个事件就是"空中到点炸" ⇒ 只画 `#naAir` 空炸环、
   不画地面圈。
4. **举雷姿势只保持 0.45s**：`20-player.js` 的手雷动作靠 `p.nadeThrowT`（`NADE_ANIM_T=0.45`）**衰减计时**
   驱动（按"一次性投掷"写的），衰减完就回基准持枪姿态；同一处 `handK` 也回到 1 ⇒ **手臂 IK 把双手抓回枪上**；
   且第三人称手上一直挂着步枪模型（`av._gun` 全程可见，只在 `nadeK>0` 的 0.45s 内隐藏）。

## 3. 落地（批2 口径为准）

### 3.1 触发引信 = 双条件（单源 `nadeStep`）

- `00-config.js`：`NADE_IMPACT` / `NADE_ARM_T` **删除**，改为 `NADE_ARMED_BY_FUSE={frag,smoke,incin}`
  —— 表内 = "引信到点才武装"；**表外**（反坦克炸药/航弹/迫击炮弹）= 出手即武装（老口径零变化）。
- `13-combat.js nadeStep`：`fuse-=dt` 照走（**举雷期也走**），但**到点不再引爆**；引爆 = `armed && contact`：
  - 接触三档：① 触地（含落定）② 敌方士兵躯干球（`nadeContactTarget`，**只对表内弹种**、**只认敌方**）
    ③ 载具 2.6m 触发圈 / 撞墙（**只对表外弹种**，撞墙即炸是它们的老口径）；
  - ⇒ 普通手雷**撞墙不炸**（墙不是地面也不是合法目标），照旧弹跳，落到地上再炸；**没有空炸**。
  - 旧版 `updateNades` 里那句 `n.fuse=Math.min(n.fuse,0.02)`（撞墙改引信、下一步收口）随之删除 ——
    它是"预演与实弹差一步"的最后一处，现在接触口径全在 `nadeStep` 内收口。
- `20-player.js`：手中自爆段 → `if(p.nadeHeld) p.nadeFuse=Math.max(0,p.nadeFuse-dt)`（**保留计时、绝不自爆**）。
- 入水哑火（深水 >0.6m）仍**排在触发判据之前**（塔拉瓦口径：海底不炸，潜水者不被反炸）。

### 3.2 出手点/方向单源（`20-player.js`）

- 新增 `playerThrowOrigin()`：**右手**（眼位右偏 0.24m、下压 0.30m）—— 起点偏出相机轴线；
- 新增 `playerThrowDir(o)`：从出手点指向 `tpAimPoint(camF)`（准星命中点，含士兵/载具/世界几何，
  与 `fireBullet` 的 `playerFireOrigin/playerAimDir` 同一纪律）；
- `18-game releaseNade` 与 `22-hud updateNadeArc` **逐字同源**调用（旧的两处 `camera.position` 全删）；
- 效果：一人称看到"从右下角划出、远处收敛回准星"的视差（点串屏幕 x 展开 50px；**旧起点对照组 0px**）；
  三人称从人手上飞出、与一人称形状不同（首点偏移 55.9px → 661.8px）。

### 3.3 预演显示（`22-hud.js`）

- **总是画**贴地爆圈 + 0.45m 弹着点小圈 + 中心点（`#naBlast/#naSpot/#naDot`）；`#naAir` 空炸环只保留给
  唯一仍可能"爆点在半空"的一档：**撞敌躯干**（此时地面圈照画，空炸环标真实爆点）。
- 入水哑火档给 `#nadeArc` 加 `.naWater` 冷色降档（圈仍在，但换冷色虚线 —— 免得"看着要炸其实哑火"）。
- 预演物理仍是 `nadeStep` 单源（弹跳/撞墙折线/入水/触地/撞敌全部按实弹算），`#naDot` 与真弹爆点
  投影同点（实测屏距 0.1~0.2px）。

### 3.4 举雷待发 + 三人称手上真雷（`20-player.js`，`10-viewmodel.js` 无需改）

- 新增 `playerNadeReady(p)` 单源判据：按住持雷，或刚松手但出手帧未到（`VM.state==='nade'` 且弧未开始）。
- 姿态机：`nadeHold` 分支 = **蓄力位姿常驻**（与投掷弧起点同一姿态 ⇒ 松手无缝接上）；`handK` 在该态为 0
  —— 否则计时一衰减完，IK 会把双手抓回枪上。
- `avNadeSync`：右手 `hand` 上挂**四件真雷模**（`buildNadeMesh` 单源 × `NADE_WORLD_SCALE`，与一人称手上件、
  出手件同模），按 `vmNadeKind()` 显隐；出手帧（`k>0.5` 调 `releaseNade`）之后脱手，死亡时由 `avNadeHide` 收。
- 朝向取单位阵（手局部 +y ≈ 引信朝上，与一人称 VM 手上件同朝向），`position.y=-0.02` 把弹体从拳心推向掌外。

## 6. 边界与未做（如实登记）

- **Bot（14-bots）手上不加雷模**：它们的投掷是一次性 swing，没有"举雷待发"段；本批只做玩家侧。
  如需 Bot 也握雷，另开一批（挂点与姿态同样是 `armR.hand`）。
- **弹道剖面按裁定保持"平直快球"**：弧线本身仍然平（30m 只抬 0.3m），空间感来自"右手起点的视差 +
  始终显示的贴地落点圈"，而不是弧高。若后续想要"看得见的抛物线"，需要改的是初速剖面（批2 问项里
  的另两个选项：瞄准点自适应中抛 / 固定初速高抛），属**未采纳**方案。
- **手雷落地会弹跳滚走**：引信到点在哪停就在哪炸，滚走距离随地形 20~44m 都实测到过。预演逐帧同算，
  所以圈 = 真实爆点（B3「指哪炸哪」钉死）；但"投出去 30m 落在远处"这一手感如需收紧，要动的是弹跳
  阻尼（`st.vel.x*=0.68` 那三行），不在本批范围。
- **瞄准点很近时落点会缩短**（出手方向汇聚准星命中点：站在墙前/低头看脚时命中点很近）—— 这是
  "指哪炸哪"的正常行为，探针场地因此加了"正前方 45m 走廊净空"要求。
- **一人称 VM 手上件的位置未动**（仍是原持雷位），与新的世界出手点（右手）在屏幕上不完全重合：
  预演点串从屏幕右侧划出后向准星收敛，**落点与实弹严格一致**（B3 钉死）；若要求"点串起点贴住
  VM 手上件"，属观感微调，另开一批（VM 是独立的 vmScene 叠加层，世界米与 VM 空间需要一次标定）。
- **Bot 的投掷弹道未受影响**：14-bots 有自己的弹道解（`tof` 解），不读 NADE_THROW、也不读新的
  出手点函数（它们的投掷仍从 `eye` 出发）—— 本批只改玩家侧，Bot 手感零变化。
