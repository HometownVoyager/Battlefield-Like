## 2. 设计决定与口径

### 2.1 举雷取消的边界
- **只收「哨兵持雷段」**（`VM.state==='nade' && stateDur>10`，即按住 G/3/4/6 瞄准期）。松手后的出手弧（0.55s，`nadeHeld` 已 false）**不属于可中止段**——雷已/即将脱手，`vmAbortAction` 不碰它。
- **取消不消耗雷**：`cancelReadBar` 只摘 `nadeHeld`，`nadeCount` 不减、引信下次举起时重新置满（19-input 举起处赋 `NADE_FUSE_T`）。
- **左键不取消举雷**（本批唯一一条有意例外）：19-input mousedown 的取消门加了负条件 `!(VM.state==='nade'&&player.nadeHeld)`。理由：举雷是"按住瞄准"的持续态，左键在枪上本无语义（nade 态不可开火），误点左键就把雷收掉是陷阱不是便利；**收雷只有 X / 读条上的 ✕ 两条有意路径**。包扎/拆除/前摇/换弹的左键取消原样保留（"想开枪替代读条"的直觉成立）。举雷期间其余读条结构上不可能同时活跃（VM 单值状态机互斥），一个负条件即充分。
- **观战举雷同享取消**（观战四弹种 2026-10-24 起；此前观战举雷同样收不回，顺带修掉）。

### 2.2 打断机制（与包扎同款三路）
1. **受击打断**（18-game `damage`）：任意来源伤害 → `cancelReadBar` → 弹「举雷被打断!/换弹被打断!」（链在包扎/拆除/前摇之后，前缀文案不变）。
2. **被别的行动抢占**：F 取弹药/B 建造等抢走 VM.state 前先 `vmAbortAction()`（幂等）——换弹中被抢走时弹匣正被搬在半路，不归位就是"枪缺弹匣"滞留（与 2026-10-12 包扎绷带卷滞留同族病，本批修复）。
3. **上车/上炮**：VM 冻结（24-main 不跑 updateViewModel），换弹下车自续走（既有行为不变）；HUD 读条带座位门不在驾驶位显示。

### 2.3 读条显示（22-hud 通用读条，五条互斥）
- **举雷**：普通雷 = 引信倒数条（fill=烧掉比例，分母 `NADE_FUSE_T`；烧满即"触物即炸"），标签「手雷 · 引信 {0}s · X 收回」；AT/烟雾/燃烧 = 引信 99 哨兵无计时，满条标签「{弹种} · X 收回」。
- **换弹**：标签「换弹中: {0}s」（剩余秒数），fill=进度。座位门清单与 24-main 的 updateViewModel 门逐字同源。
- 优先级链：拆除 > 前摇 > 包扎 > 举雷 > 换弹（结构上互斥，只防同帧竞态）。

### 2.4 补给弹药新账（doGrabResolve）
- **旧**：`s.mag=s.def.mag; s.reserve=s.def.reserve`（弹夹直接满+备用顶满）。
- **新**：`s.reserve=s.def.reserve+s.def.mag`，**mag 原样不动**。汤普森例：备用 300→330（超上限一匣），弹夹打了几发就几发，要自己按 R。
- **总账不亏**：超出量恰是一个弹夹——空弹夹拾取后换一次弹，mag 30 + reserve 300，与旧版双满完全一致；区别只是多一道装填手续（用户指定口径）。
- 投掷物/绷带补给不变；观战 0.5s 无限补给（20-player）与出生配装维持双满，**不在此列**。
- 拿取时机/流程不变（仍是原 0.85s grab 动作，第 0.45 处结算——用户"仍是瞬时拿取"指流程不变，本批未动时机）。

### 2.5 模型归位单源 vmReloadRestore()
弹匣（p0/r0+可见）/弹夹（p0/r0+隐）/火箭弹（隐）/枪栓（z0）/拉机柄（rot 0）/滑轨（z0）六件。**自然走完与被中止走同一份**。两个配套捕获修正：
- 栓 z0 旧版只对「无拉机柄的枪」捕获（`if(g.bolt&&!g.boltHandle)`）——带拉机柄的栓动枪 z0 永远空着，中止后无从归位；改无条件下捕获（vmEquip 后第一帧=draw 态，部件都在静止位，值恒真）。
- slide 三把手枪静止 z 各不同（-0.03 / 0.01 / -0.02），换弹分支的基底 -0.02 只是其一——同改 z0 捕获，不写死。

## 5. 实机验收清单（请按序过一遍）

1. **举雷取消**：按住 G 举雷 → 按 X → 雷收回、枪回手、手雷数量不减；再按 G 可重举（引信重新 3.8s）。

3. **举雷打断**：持雷状态下被击中 → 弹「举雷被打断!」、雷收回不消耗。
4. **举雷左键无事**：举雷中点左键——雷**不**应收回（左键不是取消路径）。
5. **换弹读条/取消**：R 换弹出现进度条 → 按 X 取消 → 弹匣归位、弹数不变；取消后立即开火正常（取消那一击不走火）。
6. **换弹打断**：换弹中被击中 → 弹「换弹被打断!」、弹数不变。
7. **换弹自然走完**：不受干扰的换弹照旧完成（弹夹填满、备用扣减）。
8. **换弹+上车**（★反馈轮 20261025b 修订）：换弹中进坦克/上炮/登艇——换弹**被打断**（弹数不变），下车后需重新按 R（不再是"下车自续走"，见 §6 裁定①）。
9. **补给新账**：弹药箱/运输车/补给点按 F → 弹夹**不满**（打了几发就几发）、备用弹超上限一匣（汤普森显 /330）；按 R 装填后备用恰好回到上限内。

### 6.1 裁定①：交互动作抢占读条（stealBar 单源）

- **新单源** `player.stealBar()`（18-game，紧挨 cancelReadBar）：安静收掉当前读条（账目+模型两层，与 X/受击同一出口；新动作自身的提示就是反馈，不叠"已取消"）。
- **调用点=各动作/交互入口"确认会起步"之后**（空按不抢——无目标按 F、冷却中按 V、同槽按 1、满血/没绷带按 H、没雷按 G/3/4/6、离炮太远按 6 回收，都不白丢读条）：
  - **19-input 动作键**：V 近战（座位/冷却门外移后抢）/ G·3·4·6 举雷 / H 包扎 / B 拆除·建造（拆除的"再按取消"分支仍在前）/ 6 迫击炮架设·回收（方向门过了才抢）/ 1·2·4 换枪（`switchSlot(i,viaKey)`）/ R 装填（`tryReload(viaKey)`）。
  - **20-player F 交互栈 14 处**：迫击炮/机枪/反坦克炮/防空炮前摇 ×4、上坦克、登艇、登舰（地面+艇上并靠）、舰载机（地面+甲板）、甲板上炮塔、甲板跳海、5 处取物（取物点由裸 `vmAbortAction()` 升级为 `stealBar()`——连 `nadeHeld/bandaging` 账目旗一起收，上一版只收模型层会留 `nadeHeld=true` 悬空）。
  - **06-engineering 建造**：前置点移到全部早退之后（点数不足/位置非法不再白抢）。
- **两条防误伤口径**：
  - **同键重按不抢**：换弹中再按 R = 维持换弹不重启（进度不白丢）；举雷中重按**同种**投掷键 = 维持（引信继续烧，烹饪不重置）；举着别种雷按 G/3/4/6 = 换举（旧雷收回不消耗、新雷引信全长起烧）。
  - **系统侧不抢**：`tryReload(viaKey)`/`switchSlot(i,viaKey)` 的抢占只在**按键**带 `viaKey`（键盘三处 + 手柄 LS 切枪）；空仓自动换弹（20-player 的 click/timeout）、再部署/观战补装等程序调用**不带**——自动续弹绝不能把玩家举着的雷抢走。
- **顺带修复**：上坦克分支旧版只摘 `nadeHeld`、`VM.state='reload'` 会冻在车上（下车自续），与裁定①冲突——现统一为打断。

### 6.2 裁定②：受伤打断门槛 = 单次伤害 >25

- 新单源 `READBAR_DMG_GATE=25`（00-config）；18-game `damage` 的读条打断链改为 `amt>READBAR_DMG_GATE && readBarActive()`。
- **门槛判在减免后的最终 amt**（伞降乘数/连杀减伤之后）；**死亡清账（die 内）仍无条件收**。
- 效果：枪弹蹭伤、火蚀跳伤、严寒/激流小跳伤（每帧 2 上下的）不再打断包扎/拆除/前摇/举雷/换弹；爆炸/狙击/近战这类 >25 的单发重创才打断。**门是全读条族统一口径**（含包扎，随用户"受伤打断机制"整体裁定）。

### 6.3 顺手修：草丛实例批越界（他批未提交代码，A/B 归因在案）

- 病根：05c-layouts 草丛实例批 `cap=r²·2.1` 但循环发 `cap*2` 个候选，通过率高时 `k` 越过 cap ⇒ `InstancedMesh.setMatrixAt` 越界——**实机（真 three）= 世界构建即崩**；探针（边界检查桩）= verify-sink 稳定红（上轮全量唯一账外红）。
- 修法：`k>=cap` 时 `continue`（不 break），且旋转/缩放两发 `wr()` **提前消费**——RNG 流与旧跑逐位一致（同种子可复现、procgen 基线指纹不动），只跳过越界候选的侧效应。
- 归因：`git diff` 该段全在 20261024e 批 `+` 行内（HEAD 无此代码）；与本批 8 文件零重叠。修后 verify-sink **5/5 稳绿**、verify-procgen 535/0、batch-f 30/0、layouts 全过。

### 6.5 实机验收清单（反馈轮追加）
