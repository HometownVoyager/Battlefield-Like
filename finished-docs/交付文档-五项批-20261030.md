## 2. 落地明细

### ① 票尽观战部署放行
- 新单源 `player.specWillBe()`（18-game）：返回**本次部署解决后**的观战态——`specWant` 是"待生效"意图（要到 deployPlayer 才落进 spectator），门必须问"解决后"而不是"现在"；`specWant=false` 显式关与未设都返回 false。
- 四处门全部改 `tickets<=0 && !specWillBe()` 才禁用/拦截：23-deploy 部署按钮 disabled + deployPlayer 早退、22-hud deployBtn onclick、24-main 死亡页每帧 disabled 刷新。
- 部署页票尽提示双文案：有观战意图 →「⚠ 己方兵力已耗尽 · 部署将以观战身份入场」；无 → 原文案（等待清场结算）。
- 正确性依据：`fieldCount()` 本就排除观战者（21-match），清场判定 / 最后一人 30s 倒计时 / 双归零豁免均不受观战部署影响；观战部署不扣票（die 才扣）。

### ②③ 读条交互批
- 新单源 `player.barStealArmed(key)`（18-game）：无读条 → 直通放行并清账；读条中首按 → 记键+时间戳、返回 false（不抢）；`BAR_ARM_WIN` 内**同键**再按 → 放行（账清空）。**不代抢**——抢占仍由调用方在"确认起步"处 `stealBar()`，第二次按时目标消失/起步失败也不白丢读条。
- 打断双击门接线 **27 处**：19-input 11 处（近战 N / 手雷 G / AT雷 3 / 烟雾 4 / 燃烧 6 / 迫击炮架设 6 / 包扎 H / 建造拆除 B / 换弹 R / 换枪 `SW+槽位`）/ 20-player tryInteract F 交互栈 14 处（登舰×2、取物×5、上炮塔、登机×2、跳海、上迫击炮、上坦克、登艇、登舰）/ 06-engineering 2 处（迫击炮回收、建造）。

- HUD：读条标签追加「▶ 再按一次打断」（武装态 0.5s 窗口内显示，22-hud）。
- 账目卫生：`barArmKey` 在 cancelReadBar（含 stealBar/受击/X/左键）与四处**自然走完**点（包扎/前摇/拆除回收/换弹 finishReload）清账——旧键不得残留到下一条读条的双击窗里。

## 6. 实机验收关注点

1. **①** 把己方兵力打空后阵亡：部署页出现「⚠ 己方兵力已耗尽 · 部署将以观战身份入场」且按钮**可点**；点部署 → 以观战者入场（免伤/不被索敌/幽灵坦克 F 可用），清场阶段照常推进到结算；观战开关**关着**时按钮照旧禁用。开关从关到开（部署页兵种卡点开）后按钮应在下一帧亮起。
2. **②** 包扎中连按 H / 回收迫击炮中连按 6 / 拆除中连按 B / 上炮前摇中点 F / 换弹中连按 R：读条都应**略微变快**且不取消、不重启；频率感≈每按一次快 2.5%。
3. **③** 换弹中按 G（只按一下）：读条**不**被打断，读条上出现「▶ 再按一次打断」；0.5s 内再按 G → 换弹被打断、举雷起步。换键（先 G 后 3）不共用确认。X / 左键 / 大伤害 / 移动仍是单击立即打断。
4. **③注意** F 交互栈也双击了：读条中上坦克/上艇/补给需要**连按两次 F**（第一次只亮提示）——紧急逃生时多按一下属预期。
5. **④** 观战局（含票尽观战入场的局）打完：结算页标题「对 局 结 束」+ 灰色眼睛图标 + 副标题「胜方 · 某某军」；得分/战绩卡/兵力条/「不计入历史记录」都在。普通局结算**逐字节不变**（胜负金/红图标照旧）。
6. **⑤** 迫击炮：命中圈肉眼可见变小（与手雷同级偏小）、满血兵中心命中**不再必死**（100 伤 + 半径 5.25m 衰减）、连发间隔明显变长（玩家 4.5s）；敌方 Bot 迫击炮节奏明显变慢（6~9s）。连杀增益下的加速仍在。
7. **双语**：语言切 EN 后，新文案（观战部署提示/再按一次打断/对局结束/胜方）均有英文。
