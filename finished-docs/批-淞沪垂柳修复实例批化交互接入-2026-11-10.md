### ① 连接重写（js/05b-props.js）
- 主枝根**钉在干顶**：枝根 = 干顶世界位 + 枝向×0.58 − 0.12 下嵌（顺干倾斜，tilt 从 wt 四元数反解）。
- 冠片 7 片蓬进枝梢高度带 [3.0,4.0]（旧 h∈[2.6,3.6] 整体上抬 0.4），半径钳进枝梢回转圆。

## 探针坑（本批新五则）
1. **willowN 陷阱**：采集脚本 `__wtLog.length`=**调用数**（79），TREE_LIVE 接受数=75——拒绝在 wr 消耗前 early-return。golden 钉应钉"保序子列"而非等长逐位；"拒绝 N"的口径=调用数−接受数（gi 剩余量不是拒绝数，被拒调用在序列中部被 while 跳过时 gi 会走满）。
2. **沉入断言写法**：全沉终态=零缩放（平移分量也归 0），不能拿"沉前 y>0.5"当判据；须下沉增量（rest 与 rest+1.8 双采样，≥1m）+ 终态零缩放 + 标死三段式。
3. **NEG 整行替换 if 留孤儿 else**=语法错（N8 首版）；用 `if(false)` 门保持 else 合法（乔木空路径 setMatrixAt(NaN) 是静默 no-op，不炸）。
4. **NEG 摘 flushWillows（WLOW_IM=null）**：所有直读 WLOW_IM 的 G 表达式与 sim 循环（updateBurningTrees 焦黑分支 / updateFallingTrees 分派）都会抛 TypeError——阴性轮要的是红名不是崩溃，全部加 `!!WLOW_IM` 短路 + 循环 try/catch。
5. **N1 kind 降级让 W1~W4 全 undefined** → 各行为段 `[skip]` 守卫（同 N9 对 WLOW_IM 的守卫思路）。

### 病根（两处同型，皆本批新代码）

vendor `three.min.js` 的 `Matrix4.compose` 读四元数的**内部私有字段 `_x/_y/_z/_w`**（minified 实证：`compose(t,e,n){const i=this.elements,r=e._x,s=e._y,a=e._z,o=e._w,…}`），而本批两处矩阵写入用了**普通对象四元数**：

1. `js/05b-props.js:275` `flushWillows`：`_q={x:0,y:0,z:0,w:1}`（初始 23 实例×75 棵的建模矩阵）——注释误信「compose 只读分量」；

2. `js/04b-fire.js:556` `willowInstanceMatrices`：`_wlQ={x:0,y:0,z:0,w:1}`（倒伏/沉入/焦黑三态的运行期矩阵）。

compose 拿到 4 个 undefined → 旋转+缩放分量全 NaN → 顶点被 GPU 整批丢弃=**实机整批隐形**。平移分量 te[12..14] 由 position 直接写入、不受四元数影响 ⇒ 探针 ②-9（平移钉）/③（探针侧手算复算，不读矩阵）/④（沉入平移增量钉）**全漏检**——39 绿照跑。仓库既有 compose 用法（flushTreeBatch/flushBushes）都是真 `new THREE.Quaternion()`，本批为「沙箱 Quaternion 无 set/multiply」纪律新写时执行过头变成了普通对象。

### 修

两处声明改 `new THREE.Quaternion()` 真实例，按分量赋值（`.x=…` 等）走 setter 落 `_x`——不调 `.set/.multiply` 纪律不破；bootstub 的 Quaternion 可构造、compose 为 no-op，桩探针无感；与 flushTreeBatch/flushBushes 既有先例同款。

### 新律三条（入记忆）

1. **compose/实例矩阵路径禁普通对象四元数**——一律真 `THREE.Quaternion` 实例+按分量赋值；「沙箱 Quaternion 无 set/multiply」只挡方法调用，不挡实例化。
