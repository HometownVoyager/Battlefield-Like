## 1. 修复① 附身武器镜像单源 (严重系统性 BUG)

### 1.1 病根链 (排查结论: 三层叠加)

「视角武器 ≠ 宿主实际武器」不是单点错, 是**三层各错一点**的系统性漂移:

| 层 | 病根 | 位置 |
|---|---|---|
| 槽位层 | Bot **没有 curW 概念**: 当前武器由各开火分支各自决定 (AT/迫击炮兵对人员目标**永远打副槽手枪**, 主槽火箭筒只对装甲开火); "手里那把"的既成事实台账是 `heldWpnKey`, 但只有挂枪函数在维护 | js/14-bots.js 各开火分支 / switchVisualGun |
| 附身层 | `specViewPossess`/`specViewTick` **钉死 slots[0]** (主武器槽) —— 附身瞬间宿主已持副武器 (如 AT 兵自卫) 或附身中宿主切了枪, 视角永远停在主武器 | js/20-player.js specViewPossess / specViewTick 两分支 |
| 动作层 | `svHostActionMirror` 只镜像主武器 `reloadT`, 副武器换弹账 `pReloadT` 不镜像; 火箭筒 `fireRocket` 无出膛反馈钩 (旧版只挂枪械弹) ⇒ 视角里宿主"拿火箭筒开枪械火"的错位观感 | js/20-player.js / js/13-combat.js fireRocket |

用户看到的"手持火箭筒却连续打枪械子弹" = AT 兵对人员目标按设计打手枪自卫 (14-bots:2258-2266) + 附身视角钉在主槽火箭筒 —— **行为本身是 Bot AI 设计, 错的是呈现层没有跟随**。

### 1.2 落地 (单源两函数)

**`svHostCurSlot(h)`** (20-player, 台账→槽位单源):
- `heldWpnKey` 存在且 ≠ `wpnKey` 且 slots[1].key===heldWpnKey ⇒ 返回 slots[1] (宿主手里那把);
- 否则退 slots[0] —— **兼容守卫**: 既有 specview 探针的假宿主 (无 heldWpnKey 字段结构) 行为逐位不变。

**`svHostWeaponMirror(h)`** (20-player, 呈现单源): curW 钉到 svHostCurSlot(h) + VM 换枪 —— 门 = `VM.key!==w.key && (VM.state==='idle'||VM.state==='draw')` (镜像换弹/举雷/包扎中不抢枪, 打断归位由 svHostActionMirror/vmAbortAction 收, 下一帧自然补换)。

**接线四处** (全部走上面两单源):
1. `specViewPossess`: `svHostCurSlot(b)` 替换钉死 slots[0] —— 附身瞬间宿主已持副武器同样跟装; VM 即刻换装;
2. `specViewTick` 两分支 ×2: `svHostWeaponMirror(h)` 替换 curW 钉定行 —— 附身中宿主切枪, 视角逐帧跟随;
3. `svHostActionMirror` 插副武器分支 (主武器分支逐字不动, verify-specview 源码锚保住): `_side` = svHostCurSlot(h)===slots[1] ⇒ `pReloadT>0` 镜像 VM reload (时长=宿主剩余) / 归零而弹匣未满 ⇒ vmAbortAction 同帧收 (与主武器打断语义一致);
4. `22-hud` 弹药面板同源: `svHostCurSlot(h)` 替换 slots[0] —— 枪名/弹数/备弹跟宿主手里那把。

**5. `13-combat fireRocket` 出膛反馈钩**: 与 fireBullet 同款 `svHostFireFx(def)` —— 宿主打火箭, 视角同样有后坐/枪口焰 (旧版只挂枪械弹)。

### 1.3 边界口径 (已核)

- **换弹中不切枪**: fireGate (14-bots:2243) 要求 reloadT≤0 才进开火分支 ⇒ 主武器换弹期间不可能触发 switchVisualGun, "换弹换到一半枪变了"不存在;
- **fireRocket 打在 pReloadT 期间**: 下一 tick `_side` 分支自愈归位 (弹匣未满才 abort, 已满则自然走完);
- **vmFireKick 对任意 VM.key 成立** (读 WPN_DEFS[VM.key]) ⇒ 火箭筒后坐量正确;
- **只读借眼不破**: 全链零写宿主账 (探针 ④ "宿主弹药账零写入" 钉死)。

## 2. 修复② 第三人称手枪差异化

### 2.1 三枪族造型 (用户裁定"三款枪族造型")

`gunKindOf`: `if(d.pistol) return 'pistol';` (旧版 `return 'smg'` —— 第三人称拿的是**冲锋枪/步枪模型**, 这是"切副武器外观无变化"的直接病根)。

`worldGunModel` 新 pistol 分支, 与第一人称 buildGunModel 的手枪族谱一一对应 (09-weapons):

| 枪族 | 键 | 造型要点 |
|---|---|---|
| **colt 柯尔特式** | m1911 / p38 / tt33 | 套筒 (0.17 长) + 枪管 + 短握把 (rx −0.25) + 小弹匣 + 准星 |
| **broom 驳壳枪** | c96 | 方机匣 + 细枪管 + **前置弹匣** + 扫帚柄 (rx 0.25) |
| **nambu 南部十四年式** | nambu | 细长枪管 + 斜握把 (rx −0.4) + 短护圈 |

坐标系同各枪: 原点≈扳机位, +z=握把端 / −z=枪口端 (mountGunModel 转 π 后枪口朝前); 抓握点由 gunGeomStations 按本几何现算, 双手 IK 自动落位, 无锚点表。

### 2.2 双手持枪 (用户裁定)

**不加 GUN_HOLD_BY_KIND.pistol 表项** = 走默认双手持枪机械 + armIK (左手反解到护木站位); 通信仪单手表 (GUN_HOLD_BY_KIND.radio) 不受影响。

### 2.3 挂点重定位 (a21-j 全量复测定位, 本批最大暗礁)

首版挂点 {−0.13,0.34,0.24} (站) / {−0.20,dy0.12,dz0.38} (匍) 落地后 `dev/verify-a21-j.js` 冒烟**当场抓出几何回归**: ④′ 匍匐左手到枪面 0.184 (Bot) / 0.199 (玩家) > 0.06, ①″ 站/瞄/蹲 +3 组越界。

**A/B 归因** (内存还原旧 pistol→'smg' 映射对照, sha256 校验复原): 旧映射 ④′ 双手全绿 (0.005/0.056 Bot, 0.000/0.037 玩家) ⇒ 回归确系本批手枪模型/挂点引入, 非既有账。

**根因** (沙箱内包 armIK/gunForePoint 逐帧记录实测): 匍匐枪角 rx≈−1.5 把仅 0.078m 的护木站位旋到**躯干正前 (+y)**, 挂点又收在胸前 ⇒ 左肩 (0.28,0.50,0) 到目标 (−0.189,0.526,−0.072) 几乎**纯横向 0.469m**; 两连杆弯肘的横向包络 hy(d)=L1+L2·cosB(d) 在 d=0.475 时仅 **0.372m** —— 直距 0.475 ≤ 臂长 0.62, 既有 gunAxisPoint 走 t 回退的判据 (只测直距) 测不出这种"直距够但横向包络不够"的失效。长枪匍匐没事是因为枪前伸得远, 目标是斜前向。

**定位扫描** (临时沙箱 5 键×4 姿态×双路径全组合, 探针同口径量测): 站姿 I 档 **{−0.17, 0.42, 0.33}** + 匍匐 **{−0.24, dy0.12, dz0.62}** 全绿 —— 手枪**无枪托**, 零接触优于"抵肩接触" (①″ 四姿态×双路径躯干盒 0 相交 / ①′ 头盒 0 相交 / ④′ 双手 L=R=0); 匍匐 dz≈0.62 ≈ 步枪档 0.545 = 双臂前伸持手枪的自然匍匐姿态。南部式握把斜置盒世界 AABB 后伸超柯尔特族 2mm (蹲姿 2mm 侵盒), 握把 0.05→0.04 收齐。

**修复后 a21-j**: ④′ Bot 0.005/0.056 ✓ · 玩家 0.000/0.037 ✓ (**与旧映射基线逐位相同**), ①″ Bot 25 / 玩家 29 (**回到基线数**), ①′ Bot 0 ✓ / 玩家 2 (预存, A/B 同红), ② 挂点单源 ✓。剩余红全部为预存账 (a21-j 不在 run-all 名册)。

### 2.4 前推量

`CARRIED_FWD.pistol=0.06` (枪短, 沿用步枪 0.30 会把手枪推出手外, IK 钳臂长 ⇒ 脱手)。
