**成本结构判定（按占比排序）**：

1. **Draw call 体量是第一瓶颈**：主 pass 每帧对 1200~11000 个独立 Mesh 逐件绘制（视锥裁剪后仍是数千），阴影 pass 再对 84~2066 个投射者整遍重画。`finished-docs/性能优化与架构缺陷重构工程指导-20261007.md` 声称 Phase 2"静态建筑按材合并"已 100% 落地——**与代码事实不符**：全库仅有 `05-world.js` 的 `mergeBoxItems/_bldBatch`（对 `solidBox` 构件按材质合并）这一条腿落地，其余构建路径（05a 直接 `mesh()`、门窗细节、可毁组、残件）仍是逐件 Mesh。
2. **灯数翻转造成的着色器抖动是暗光图（夜/雨）的周期性微卡顿源**：three r152 前向渲染中，**可见灯的数量**参与所有材质的 program 缓存键。旧版火源灯（85m 硬门）、大灯真灯池（60m 硬门）随玩家移动/载具生死反复翻转可见性——每次翻转全场 300~850 个材质逐个重走 `getProgram` 查表 + GPU 每片元光环数变化。淞沪/滇缅/胡康/铁底湾**白天也走夜间装备链**（`isDarkEnvironment()` 对 `precip==='rain'` 为真），受害面比"夜间"直觉大。
3. **夜间链每帧零散分配与逐帧排序**：`nightGearTick`/`updateFireLights` 旧版每帧新建候选数组 + 闭包比较器 + 全候选重收重排（火源位置静态，纯浪费）；手电起点 `eye.clone().add(...).add(V3())` 每帧 3 个新向量——违反《性能优化指导》军规 #2"热循环零分配"。
4. **Bot 手电射线无节流**：每个开灯 Bot 每帧一发 `raycastWorld` 全场景 DDA（08-effects 大灯 2026-10-10 已节流 0.12s，14-bots 同款路径漏了）。
5. **非本批处理项（如实记录）**：q1/q2 画质在 canvas 上挂 CSS `filter`（全屏合成滤镜，每帧一次浏览器全屏 composite）；`antialias:true` + q2 像素比上限 2.0 的填充率；爆炸共用 `flashLight` 常驻可见（**这是有意设计**——常驻可保灯数恒定，避免每次爆炸翻两次灯态，本批保持）；灯池总量本身有界（真光源同屏 ≤3 的预算红线未破）。

## 二、本批修复（4 项，全部可回滚、低风险）

### ① 阴影 pass 半频刷新（`02-scene.js` + `24-main.js`）
- 新增 `shadowRefreshTick()`：**q0/q1 画质阴影视锥 30Hz 刷新**（奇偶帧置 `shadowMap.needsUpdate`，r152 渲染一次自动回落），**q2 维持逐帧**；夜间 `sun.castShadow=false` 时恒不请求 ⇒ 阴影 pass 整体跳过；`applyQuality` 换档重灌 shadow map 后就地补一帧，避免换档当帧丢影子。
- 主循环冻结分支与战斗分支各接一处（均在 `renderer.render` 之前）。
- 效果：低/中画质下阴影 pass 的绘制量直接减半（莫斯科 2066 投射者 → 每两帧画一次）。太阳方向恒定 + 视锥纹素对齐跟随相机，30Hz 下动态投射者的影子位移在战术视距不可感知。

### ② 大灯真灯池滞回 + 夜间链零分配（`08-effects.js`）
- 真灯竞选从 60m 硬门改为 **60m 进 / 75m 出滞回**（`v._hlReal` 粘滞位）：载具贴竞选半径行驶不再每秒多次翻转灯可见性。
- 候选表/比较器/距离函数升为模块级（`_hlCands/_hlCmp/_hlD2`），距离平方入表时算一次，排序仅在 >1 个候选时发生；`distanceTo` 开方全部改缓存平方比较。
- 手电起点改复用槽 `_pfO`（`copy+addScaledVector`，零分配）。

### ③ 火源灯 85/110m 滞回 + 0.2s 扫描 + 活取源坐标（`08-effects.js`）
- 候选收集+排序 **0.2s 一轮**（火源位置静态，逐帧重收是纯浪费）；分配槽 `_fireAssign` 持久化，每帧只做 flicker 抖动。
- 点亮门从 85m 硬门改为 **85m 进 / 110m 出滞回**。
- **候选只存 src 引用、坐标活取**（`_firePos`）：开发中被行为断言抓到快照坐标会钉死 `follow` 随舰火源（04b"船开走火浮空"同病），已修正为每帧活读源位置。
- 保留 2026-10-10 的两项裁定：白天激活数压制（暗光 2 / 白天 1）与双入口单帧去重守卫（`verify-fixes-20261010-batch2` 照旧全绿）。

### ④ Bot 手电 raycast 0.12s 节流（`14-bots.js`）
- 与大灯同款：`m.flRayT` 0.12s 节流 + `m.flOccD` 缓存，未到重测帧沿用上值做光锥截断。实测 12 帧 `updateMesh` 从 12 发射线降到 2 发。

## 四、用户实机验收建议

1. 白天大图（莫斯科/柏林）q0/q1 画质走动+交火：帧率应有可感提升（阴影减半），影子跟随略有迟滞属预期（q2 不受影响）；
2. 夜间/雨天图（淞沪/滇缅/铁底湾）：开车沿燃烧残骸/开灯车队附近来回移动，原先的周期性顿挫应明显减少；
3. 大灯照明范围观感不变（60m 内照常点亮），只是出灯/掉灯的边界不再抖动。

## 五、后续建议（本批不做，按收益排序）

1. **静态合批收尾（Draw Call 治理，最大头）**：把《20261007 指导》Phase 2 真正落地——05a 直接 `mesh()` 的永久件按材质合并（须在共面消解/世界快照之后、避开可毁组与 sink 动画件）；地形四叉树分块恢复视锥裁剪。完成后主 pass 绘制量有望降一个数量级。
2. **《性能优化指导》文档状态勘误**：其"已全面落地 100%"与代码不符，建议改为分项勾选，避免后续批次误信。
3. q1/q2 的 CSS 全屏滤镜（`renderer.domElement.style.filter`）如仍不达标，可评估移入 shader 后处理或降档默认关闭（涉及用户已认可的观感，需单独立项）。
