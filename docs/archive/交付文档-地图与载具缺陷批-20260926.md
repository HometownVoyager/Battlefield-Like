## 1. P0（五条）

### P0-1 断崖公路伏击点被挖成坑
- **现象/数字**：`03-terrain` 的出生平台默认取 `rawHeight*0.55`，而 `fullH` 白名单只含 loess/woods/island
  ⇒ 断崖公路（terr `mountain`，且**无旗点无基地**，没有任何后续平台覆盖）7 个伏击点被削 2.87~5.66m：
  南坡A `raw 8.94 → 4.92`、北坡A `12.59 → 6.92`（`dev/_spawnflat-probe.js`）。设计语义是"居高临下打谷道"，
  削成碗之后坐进去看不见公路。
- **改法**：削深上限 2m —— `削深 = 0.45·raw > 2m` 时改取 `raw − 0.4m`（浅台），否则**逐位不变**
  （其余图实测最大削深：百团 0.48 / 草原 0.50 / 0 ⇒ 无漂移；塔拉瓦唯一越线的那点被旗点全高台面覆盖）。
- **证据**：修后 7 点削深恒 0.40m（谷口集结地除外，它本来就在谷底）。同一探针。

### P0-2 守方工事摆进攻方开局旗圈（柏林/莫斯科）
- **现象**：`05c.defWorks` 遍历全旗点不校验归属，而 `23-deploy` 把"距攻方基地最近"的旗判给攻方
  ⇒ 柏林/莫斯科各 2 个攻方旗开局就带着朝自己的街垒/机枪位/铁丝网（塔拉瓦早有一份 130m 版豁免，
  注释写明这是"攻方被一路反推下海的主因之一"）。
- **改法**：`00-config.attackerFlagPicks(list)` 单源（距攻方基地最近的旗，≥5 旗取 2 / 其余取 1），
  `defWorks` 跳过这批旗、`23-deploy` 的归属改读同一支 —— 两处永不脱钩。
  ⚠ 实现细节：本函数**不读 `BASES`**（05c 的 `buildWorld()` 在 `const FLAGS/BASES` **之前**执行，
  读 BASES 会踩 const 的 TDZ），只用 `CAMPAIGN.bases` + `spawnPtsOf` 兜底。
- **证据**：`dev/_defworks-probe.js` —— 柏林/莫斯科/塔拉瓦各 2 个攻方旗，工事命中 **0**；
  守方旗仍有工事（反向对照）。`defSide` 顺带归位为 `defWorks()` 的缺省参数。

### P0-3 草原强点死袋（本批最重的一条）
- **现象/根因**：5m 导航格 + "格心开放 / 格心连线 0.9m 采样"这套**保守**判据下，
  强点那格（格心离点位最多 3.5m）会被 6~10m 环上的十来件工事/布景围成 1~5 格孤岛：
  实测每次换局有 1~3 个强点中招（风车磨坊/北原哨/麦田农庄/装甲坟场，随布景随机换人），
  落进去的兵对任何目标 `findPath` 恒 null。`dev/_steppe-pocket-probe.js` 给出逐边归因
  （"东岗 8 条边 7 条不通"、"麦田农庄 7 格孤岛"），`dev/_village-cell-dump.js` 给出写占用格的碰撞盒。
- **改法（三层，缺一不可）**：
  1. **导航判据同一条走廊**（`07-nav`）：格开放 = 格心空 **或**四象限采样 ≥3 空；
     边 = 两格心连线 **或**其两条 ±1.5m 并行线任一贯通。语义从"中线是不是空的"变成
     "3m 宽的走廊能不能过" —— 横跨走廊的墙/树篱照样三条线全挡（阴性对照仍报红），
     而落在格心的一件 0.8m 箱柜不再判死整格。
  2. **强点净空**：强点工事环外推到 9.5~11.5m（>7.5m = 3×3 格半径，<12m = 强点战圈，掩护仍算圈内）；
     全图散布（草垛/拒马）加 `spawnKeepClear(x,z,10)`；`17-emplacements` 给强点配的反坦克炮/机枪位
     侧移由 ~6m 推到 ~10m 并过同一道净空闸。
  3. **麦田农庄院口**：三木屋+谷仓外推到 ≥12m 且只在北/东两侧成环，两道院墙向里收 —— 南/西敞开成院门。
     （旧构型把村心围成一圈，是**稳定必现**的那一个死袋，与随机无关。）
- **证据**：`verify-navspots-20260926` 连跑 **13 次 boot 全 0 判罪**（修前 13 次里多次 1~3 罪，
  且麦田农庄必现）；`verify-nav-20260926` 正向 6/0 + **阴性对照 4/2 按预期报红**；
  `verify-layouts` 的"强点圈内掩护 ≥3"不变量仍过。

### P0-4 / P0-5 坦克出生朝向与落位
- **现象**：`Tank.respawn` 写死 `yaw = team0?HPI:−HPI`（"两主基东西对置"年代的产物）+ 只按队内序号横排，
  不看落点上有没有东西。实测斯大林格勒 14 台车全部背对敌基地 **138~148°**、车头离图缘仅 27m；
  雾林守线苏军第 5 台压在一个 r=0.58m 的圆柱上（`dev/_tankspawn-probe.js`）。
- **改法**：① yaw = `atan2(敌基地 − 本车)`（与 `basePos` 同一套坐标源，换图自动成立）；
  ② 新增 `tankSpawnOk(x,z,yaw)`：占用格 + 水深 ≤ 熄火门限 + 车体轴线三圆（±2.6m，与推挤同轴距）
  + 车体四角高差 ≤ 25°（口径与 `update()` 的坡度物理同源）；首选位不过则沿环向外找净位（6/10/14/18/22m × 8 向），
  全不过才退回首选位（宁可原位也不留空）。
- **证据**：`dev/_tankspawn-probe.js` 12 图：占用 0 / 压件 0 / 水深 0 / **朝敌基地差全部 0°**；
  莫斯科有一台因原地不合规被搬到 (−270.8,−37.8)（正是校验生效的样本）。

## 4. 本批有意引入的可见行为变更（实机验收重点）

1. **AT 炮 / 岸防炮上炮时的视角被钳在 ±100° 射界内**（炮不动人也不能转）——这是"视角=炮口=弹道"的代价：
   旧版是"视角自由 + 炮管跟着转"，炮口会扫过操作手/自家胸墙。下炮（E）后可自由环视。
2. **战机扫射载具现在受遮挡**：隔建筑/山梁不再刮血（旧版无视地形直接扣 3）。单发强度不变。
3. **坦克车组会打海战载具了**：塔拉瓦的守方坦克会朝登陆艇/鱼雷艇开炮并沿海岸机动
   （旧版完全无视）。注意观察坦克会不会在滩线扎堆。
4. **水深 1.2→1.35**：礁盘/浅水带（1.2~1.35m）现在陆战载具可以开过去而不熄火；
   >1.35m 仍是熄火+掉血（= 人得游泳的深度）。
5. **草原强点工事环外推到 9.5~11.5m**（视觉上更松），麦田农庄院墙朝向改变（南/西成院门）。
6. **导航走廊判据放宽**：AI/坦克现在能穿过 3m 左右的窄缝（旧版会判成整格封锁）——
   观感上"Bot 更会钻空子"，且"某个点不可达"的假失败显著减少。
7. **等飞行员 10 秒**：战机战损后若飞行员在地面活着，现在真的等 10s（旧版 ~0.07s 就把人收回座舱）。
8. **岸炮俯角变小**：面海方向压炮只能到 −15.4°（旧版可压到 −24°，但炮管在墙里）。
