## 二. D5 机瞄保留小准星

**用户原报**：「右键瞄准时仍没有准星（比如冲锋枪）。」

**病根**：`22-hud` 准星显隐分支里 `ads && !scoped`（冲锋枪/步枪等机瞄）一路 `hudShow('crosshair',false)` 且无任何替代瞄具；
只有反坦克枪（atRifle）有一条"侧偏机瞄特批"保留 5px 小准星。10-viewmodel 的"机瞄照门自然对齐屏幕中心"设计实机可读性不达标（用户已裁定要准星）。

**改动**：把 atRifle 特批分支并入通用规则 —— `player.alive && player.ads && !scoped && !onVehicle` ⇒
准星保留、`--gap: 5px`（与反坦克枪同档）。带镜武器（scoped）仍收准星走镜内分划；腰射动态 gap 不变。
逐武器表清零"举镜后无参照"的档：全武器表里非 scoped 的枪（步枪/冲锋枪/机枪/霰弹/反坦克枪…）机瞄后屏上都有小准星。

## 三. D6 坦克准星残留

**用户原报**：「开一次坦克可能导致坦克准星残留。」

**病根（实锤，一条缓存失配链）**：`tankPip/mgPip/leadPip` 是**双写点**字段 ——
① `20a-seats` 座驾链每帧**直写** `pip.style.display='block'`（绕过 22-hud 的 hudStyle 去重缓存）；
② `22-hud` 的兜底收尾走 `hudShow('tankPip',false)`，写前查缓存：缓存里记的还是**进车前**的 'none' ⇒
出车那一帧"以为已是 none"**漏写**，DOM 里实际是 'block' 的准星原样留下 = 残留。
`_hw` 处注释（2026-09-26 性能批）早就写明"只在写点唯一处用，否则缓存失配漏写"——pips 正是违反者。
（`mgHeatWrap` 的兜底 2026-09-21 A#3 时就按 DOM 实际值写，所以热量条没有这个病——旁证。）

**改动**：新增 `hudHideReal(id)`（读 DOM 实际 display，非 none 才写，幂等、无重排开销），pips 兜底全部改走它；
与 mgHeatWrap 兜底同款口径。行为判据复现了完整病根现场（见判据）。

## 四. D7 击杀确认

**用户原报**：「击中在准星上有表示，但击杀却没有。」

**病根（登记文档定位更正）**：登记表原记"hitmarkSnd 从未以 true 调用、无视觉命中标记"——**复查后此定位不成立**：
21-match 的 `onPlayerKill/onPlayerHit`（2026-09-13 结算批引入）本来就有红/白档 + 升档音。真病根是**同帧盖档时序**：

```
fireBullet → sol.damage() → hp≤0 → die() → onPlayerKill（红档 320ms）  ← 先
           ← 返回 fireBullet → onPlayerHit（白档 140ms + remove('kill')）← 后，同一帧把红档盖回白档
```

即每一次**致命**射击，红档都被紧接着的白档当帧覆盖（onPlayerKill 旧版还没把定时器挂到 `hm._t` 上，
onPlayerHit 的 clearTimeout 清不到它）——玩家看到的永远是白档 = "击中有表示、击杀却没有"。
次要缺陷：打坦克/卡车只有 `Math.random()<0.2` 抽奖出声、无视觉标记（"打了没反馈"的抽奖感）。

**改动**：
- `13-combat` 命中步兵分支：`if(shooter.isPlayer && sr.sol.alive) onPlayerHit(...)` —— 致命一击不再补白档，击杀档由 die() 单源负责；
- `21-match onPlayerKill`：定时器挂 `hm._t` 并 clearTimeout 接管收账槽；车毁连带多杀（驾驶员 Bot.die + 2 名额
  settleCrewSlotDeath 三连进）的红档音 0.25s 合并为一响（标记仍逐杀刷新）；
- 新增 `21-match onPlayerHitVeh`：打载具 = 白档标记（与打步兵同一视觉语言）+ 音效 0.12s **确定性**节流
  （机枪泼水不连成一片，也不漏反馈）；`13-combat` 载具命中分支接线（替换随机出声）；
- `hitmarkSnd(true)` 音色升档链已有（01-audio），本批起真正可达。

## 五. D8 受击方向指示

**用户原报**：「被击中的时候没有"伤害来源方向"的表示。」

**现状复查（登记文档定位更正）**：库里其实有一套旧实现 —— `18-game player.damage` → `21-match addDirHit`，
但它是**准星旁 90px 处的 22px 小三角**（肉眼难辨，等于没有）且**只在步兵本体受击时触发**；
坦克/飞机/舰船乘员受击伤的是载具、不走 player.damage ⇒ 载具内完全无指示。
登记表"grep 零命中"结论同样不成立，如实更正。

**改动（三稿，二/三稿起因=用户对前稿的实机反馈，最终形态为用户裁定）**：
- **视觉（一稿 → 二稿 → 三稿定稿）**：一稿 60vh 大圆环 border-top 顶弧 —— 实机反馈「太大了，圆弧没尖锐、
  紧迫感和美感」；二稿 clip-path 刃形楔标（112×26 收尖斜刃 + 径向外推 0.38×短边）—— 实机反馈
  「偏离中心太远且太不规则」，且用户点名批评流程（视觉类应当先问再改，见下）；**三稿 = AskUserQuestion
  用户裁定（形状：战地式窄弧；距离：中距 ≈150px）**：等宽圆滑短弧 ≈45° —— radial-gradient 画等宽弧带
  （半径 140→164px、带心 ≈152px），conic-gradient 角向遮罩只留顶部 45°、两端各 8° 柔和渐隐，
  纯圆弧绘制天生规整无锯齿；出生 0.3s 脉冲（只动 opacity/filter）+ 红辉光；
- **流程更正（用户批评成立）**：工作规则"多交流、不闷头猜"没有视觉例外；本批二稿起改为
  **视觉/美术向改动先给带预览的选项问用户再改码**（已写入长期记忆）；
- **JS**：`addDirHit` 只写 `rotate(−rel)` 指向来向（弧带半径由 CSS 画，一/二稿的径向外推已废）；
  1s 后 0.45s 渐隐、1.5s 收账；±0.6rad 内的多次受击合并到同一条弧上（刷新角度 + 续计时）；
- **乘员通用**：新增 `21-match addVehDmgDir(vessel,attacker)` 单源（双保险：座驾 playerDriven + player 确实在座），
  `15-vehicles Tank.takeDmg` / `16-aircraft Plane.takeDmg` / `15d-naval NavalCraft.takeDmg` 三处 playerDriven
  分支接线（typeof 守卫，部分加载沙箱不炸）；步兵路径（player.damage→addDirHit）保持不变；
- 角度约定沿用旧实现（worldAng−yaw+π，rotate(−rel)，已核方向正确：来向在右 ⇒ 弧指右）。
