## 一、根因与修法（6 项）

### ① 弹药箱悬浮在船外（实机新报）
- **根因**：上批把舰桥旗从塔内挪到右舷走道（舰局部 (+8.3,+14)）后，05c 的甲板旗弹药箱仍按旗点 **±4 随机散布**——那套散布是给陆图开阔地的；`freeSpot` 只懂 2D 道具互斥、不懂舰体几何。随机到 lx=12.3（8.3+4）> 甲板半宽 9.0 ⇒ **箱子悬在舷外水面上空**（用户看到的）；随机进 |lx|<5.8 带则埋进甲板室/舰塔。
- **修法**：甲板弹药箱全面改**舰体局部锚**——
  - 00-config：12 面甲板旗各加 `crateL:[lx,lz]`、4 艘基地舰各加 `baseCrateL:[-7.9,0]`（判据全写在注释：甲板矩形内、护栏夹持线内缘 8.45<8.58/8.88、box 净空≥0.2、与中线大件同侧走道间隙≥0.84 保通行、离各炮位座圈≥2.6m 不与"上炮"抢 F、cv 侧避舰岛/弹射槽/中线跑道）；
  - 新单源 `capShipLocalXY(idx,lx,lz)`（00-config）：舰局部→t=0 世界，与 15h `capDeckBind` 的 world→local **互为逆变换**（探针 T2 往返零漂移盖章）；
  - 05c：有 `crateL` 的旗点直接按锚**强放、不走随机**（无锚旗点保留旧随机兜底，陆图路径逐位不变）；
  - 调试中抓到的第二处漏：05c 运行期 FLAGS 映射表（:2540）没拷 `crateL`/`poleH` ⇒ 箱子全走旧随机、低旗全失效——补拷两字段。

### ② F 键冲突（跳海 / 补充弹药 / 登机）
- **根因**：`tryInteract` 的甲板分支（②b）旧版**无条件 return** ⇒ 通用段的弹药箱补弹（2.6m 段）与停机登机（capNearestParkedPlane 7m 段）在甲板上**永远不可达**——箱边按 F 要么被 capGunNear 吃掉去上炮、要么弹"走到舷缘再按 F 跳海"。提示层同病：箱边漏出通用"补充弹药"提示、艇靠帮漏出"F 进入 PT 艇"，按 F 实际是跳海（审计 20"提示与判据脱节"的甲板版）。
- **修法**：甲板层优先级栈——
  **① 已在炮位 ⇒ 下炮 → ② 箱边 2.6m ⇒ 补充弹药（同参：2.6m 半径 + resupplyCd 门，与陆上完全同一支） → ③ 炮位接管半径 ⇒ 上炮 → ④ 停机 7m ⇒ 登机（Space 弹射） → ⑤ 舷缘 ⇒ 跳海**；
  提示层（updateInteractHint）整段与分派**同序重写**：箱边→"F 补充弹药"、炮位→"F 操作 X"、停机→"F 登机"、舷缘→"F 跳海"、不在舷缘→"走到舷缘再按 F 跳海"（引导文案）。i18n 补 4 条 EN 词条（跳海×2 / 登机 / 登上{0}）。
- **设计说明**：箱子锚位与各炮位座圈水平错开 ≥2.6m ⇒ 补弹与上炮没有"同时可及"的重叠区（round5 探针 T1 复核）；站在箱边且补弹冷却中按 F ⇒ 顺栈跳海（该点本就在舷缘判据内）。

### ③ capExitNow 艏艉退出点（探针揪出的既有缺陷）
- **根因**：跳海的艏艉向退出坐标写 `deck.hl*0.5`——`deck.hl` 本身已是**半长**（bb 72），再折半 = 36m ⇒ 从艏艉向 1/3 段按 F 跳海，人被"传送"到 36m 处的高炮塔旁**还在甲板上**（F 看起来没反应）。
- **修法**：`outZ = deck.hl + 1.4`（与舷侧 `outX = capDeckHW+1.4` 同余量）——落点必在甲板矩形之外，走同一条"掉海"物理路径。

### ④ 前主炮旗低旗化（上批顺手发现 b）
- **根因**：铁底湾前主炮旗 (0,+27) 距 #2 高炮塔心 (0,36) 仅 9m——#2 塔炮轴高（甲板+6.0/6.3）正落在旗面带（甲板+5.5~7.0）内，塔一转向旗面就被炮管周期性扫穿。#1/#3 塔炮轴只有甲板+3.0（平射够不着旗面），且水平距 25/75m 超主炮管长（ringR×3.30 ≈ 17.8/18.5m）——全舰只有 #2 是约束。
- **修法**：**低旗**——00-config 前主炮旗加 `poleH:4.5`，05c 旗杆几何/旗面挂高按 poleH 走（缺省 7 = 旧几何逐位，其余 10 面旗零变化），15h `capitalFlagTick` 的 poleTop 同步（21-match 布料涟漪/23b 世界还原都读它）。旗面带降到甲板+3.0~4.5，距炮管下缘（6.0−0.75=5.25）**净空 0.75m**；满俯仰（−0.06rad，仅玩家手动）时炮管下缘 4.71，仍余 0.2m。旗点原位不动 ⇒ 占领圈/旗名/i18n 零扰动。
- **已裁定接受的残余**：#1/#3 塔在玩家手动满仰角（+0.40rad）时炮管中段会扫过旗面高度带——AI 弹道仰角 ≈0.006rad 永远够不着，仅玩家刻意为之，属可接受外观个案。

### ⑤ 基地箱埋进舰体（上批顺手发现 a）
- **根因**：旧 `BASES±(3,±3)` 换算舰局部是 (±3,3)，埋在甲板室墙面里（|lx|=3 < 甲板室半宽 5.8）。
- **修法**：`baseCrateL:[-7.9,0]` 左舷走道中段——距舰心 7.9m（≤ verify-layouts 的基地箱 10m 判据；第一版 (−7.9,12) 14.4m 被 layouts 揪出超距后收拢，判据双保险生效）。陆图 `capBaseShipIdx=-1` 路径逐位同旧，13 图布局指纹零漂移。

## 三、探针工程备忘（本次新增两条）

1. **updateInteractHint 有 10Hz 状态指纹节流**（sig 含 capGunNear() 位但**不含位置**）：沙箱单发调用时 `nowT` 几乎不前进，同指纹的第二次调用会被 0.1s 门短路直接 return（不写 DOM）。游戏内每帧跑+真实时间前进，无此问题；探针验提示必须在两次调用间清 `updateInteractHint._sig/_t`。
2. **runtime FLAGS 映射表漏字段**：05c 把 CAMPAIGN.flags map 成运行期旗点对象，新增旗点字段（crateL/poleH）必须显式拷贝，否则静默回退旧行为——T1 实跑四查抓出来的（离线判据全绿、实跑全错）。
